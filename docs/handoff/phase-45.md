# Phase 45 — GnuCash Compatibility Fixture Plan

## Status

Complete. Compatibility fixture planning documentation was added, status/docs were synchronized, required checks passed, GitHub issue #22 was updated, and the phase commit was pushed.

## PM report

### Decision

Execute exactly Phase 45 from the roadmap: advance GitHub issue #22 by creating a safe plan for real-version GnuCash compatibility fixtures.

### Why

The project already has a conservative compatibility matrix for committed synthetic fixtures, but it does not yet define how to add fixtures generated by real GnuCash Desktop versions. Before Phase 46 implements any fixture or generator path, the project needs a clear safety plan covering target versions, fixture provenance, synthetic data requirements, storage policy, and acceptance tests. This phase is documentation/planning-only and deliberately avoids committing new binary fixtures or expanding controlled-write scope.

### Phase brief

- Goal: create `docs/gnucash-version-fixture-plan.md` defining target GnuCash versions, OS/source metadata, synthetic fixture data model, no-real-data rules, fixture creation/storage policy, and acceptance tests.
- Non-goals: no new product features, no fixture binary commits, no release/tag publication, no write-mode enablement, no write-scope expansion, no real financial/secrets artifacts.
- Acceptance criteria:
  - Clear plan for compatibility fixtures.
  - GitHub issue #22 updated.
  - No real data committed.
  - `PROJECT_STATUS.md`, `CHANGELOG.md`, and this handoff are synchronized.
- Safety checks:
  - `GNUCASH_WRITES_ENABLED=false` remains the documented/default state.
  - Controlled writes remain experimental post-MVP and disabled by default.
  - No real GnuCash files, `.env`, app DBs, backups, secrets, keys, tokens, screenshots, or exports are committed.
- Verification:
  - `cd apps/api && pytest -q`
  - `cd apps/web && npm run check && npm run test:auth-routes && npm run build`
  - `JWT_SECRET=dummy-validation-secret APP_ADMIN_PASSWORD=dummy docker compose config --quiet`
  - `git diff --check`

### Risks

- Fixture planning could imply broad compatibility before tests exist. Mitigation: explicit conservative language and no new compatibility guarantees.
- Future fixture work could accidentally commit personal data or large binaries. Mitigation: documented approval gates, no-real-data rules, and preference for generation/docs over binary commits.
- Compatibility work could drift into write support. Mitigation: repeated read-only/default-write constraints and no write-scope expansion.
