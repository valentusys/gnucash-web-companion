# Phase 46 — Compatibility Fixture Implementation v1

## Status

Complete. Generated disposable compatibility fixture v1 path was implemented, documentation/status were synchronized, required checks passed, GitHub issue #22 was updated, and the phase commit was pushed.

## PM report

### Decision

Execute exactly Phase 46 from the roadmap: add the first safe generated disposable compatibility fixture path and read-only validation coverage.

### Why

Phase 45 defined the compatibility fixture plan and kept GitHub issue #22 open for implementation. The project needs a practical compatibility path beyond mocks while still avoiding real financial data, large binary fixture commits, and write-scope expansion. GnuCash Desktop is not available in this environment, so Phase 46 implements the feasible generator path: a synthetic GnuCash SQLite book generated by `piecash`, loaded through the real read-only service layer, and documented honestly as not desktop-generated yet.

### Phase brief

- Goal: implement a generated disposable GnuCash SQLite compatibility fixture v1 path and tests covering account tree, transaction list, split transaction detail, and reports basic.
- Non-goals: no release/tag publication, no real GnuCash/user data, no committed binary fixture, no production compatibility claim, no PostgreSQL/MySQL/MariaDB/XML support, no write-mode enablement, no write-scope expansion.
- Acceptance criteria:
  - At least one compatibility path beyond pure mocks exists.
  - Fixture data is synthetic/disposable only.
  - Tests load the generated fixture and validate account tree, transactions, split detail, and reports.
  - `PROJECT_STATUS.md`, `CHANGELOG.md`, and handoff are synchronized.
  - GitHub issue #22 updated if `gh` is available.
- Safety checks:
  - `GNUCASH_WRITES_ENABLED=false` remains the documented/default state.
  - Controlled writes remain experimental post-MVP and disabled by default.
  - No real financial data, GnuCash books, `.env`, app DBs, backups, secrets, keys, tokens, screenshots, or exports are committed.
  - Generated fixture output path is git-ignored.
- Verification:
  - `cd apps/api && pytest -q tests/test_compatibility_fixture_v1.py`
  - `cd apps/api && pytest -q`
  - `cd apps/web && npm run check && npm run test:auth-routes && npm run build`
  - `JWT_SECRET=dummy-validation-secret APP_ADMIN_PASSWORD=dummy docker compose config --quiet`
  - `git diff --check`

### Risks

- Generated fixture could be mistaken for desktop-version coverage. Mitigation: docs and metadata explicitly say Phase 46 v1 is `piecash`-generated and not desktop-generated.
- Binary generated fixtures could be committed accidentally. Mitigation: default generator output is under `apps/api/tests/generated-fixtures/`, now git-ignored; tests generate fixtures under `tmp_path`.
- Compatibility work could drift into write behavior. Mitigation: no write code changed and read-only/default-write safety is repeated in docs/status.
