# v0.1.3-readonly Release Notes Draft

> Draft maintenance pre-release notes prepared in Phase 122.
>
> Publication status: unpublished. No `v0.1.3-readonly` git tag or GitHub release has been created. Publishing requires a separate explicit authorization from Val.
>
> This draft is a release-prep artifact only. No packages are published by this phase.

## Status

`v0.1.3-readonly` is a proposed conservative pre-alpha read-only maintenance pre-release after the published `v0.1.2-readonly` pre-release.

The project remains read-only by default. GnuCash Desktop remains the authoritative editor. This project is not production-ready, not security-audited, and not a hosted financial service. Test with disposable fixtures or copied GnuCash SQL books first, keep backups, and do not expose early deployments directly to the public internet.

Controlled-write code may exist in the repository as experimental post-MVP work, but it is outside this read-only maintenance candidate and remains disabled by default:

```text
GNUCASH_WRITES_ENABLED=false
```

## What changed since v0.1.2-readonly

This draft summarizes read-only stabilization work completed after `v0.1.2-readonly`:

- Phase 118: stabilized the desktop transaction table layout with fixed full-width columns, safe truncation for long descriptions and account names, and no needless desktop horizontal scroll; also narrowed account-tree grid sizing to avoid overflow.
- Phase 119: stripped the synthetic GnuCash `Root Account:` prefix from displayed account full-name paths while preserving account IDs, parent references, child paths, and API response shape.
- Phase 120: optimized the read-only account-detail transaction list/count path by selecting account-scoped transaction candidates through splits before applying existing query/date/amount/state/pagination and CSV semantics. Synthetic local benchmark evidence showed account-detail medians around 292–297 ms, but this remains bounded pre-alpha evidence and not a production scalability claim.
- Phase 121: fixed a Conservative dashboard summary zero-value fallback for books/fixtures where base-currency transactions exist but account balance fields report zero. The summary now falls back to split-derived base-currency asset/liability totals only when account-balance asset/liability totals are both zero and relevant base-currency balance splits exist.
- Phase 122: re-ran the read-only stability gate, Docker Compose config validation, tag/release absence checks, and tracked-file sensitive hygiene scan; prepared these unpublished release artifacts.

## Read-only maintenance value

The candidate is meaningful because it improves everyday read-only browsing stability and reporting correctness without expanding write scope:

- more stable transaction/account-tree desktop layout;
- cleaner account names without the synthetic ROOT prefix;
- faster account-detail read-only transaction retrieval on synthetic benchmark data;
- more useful Conservative dashboard summaries for base-currency books whose stored account balances are zero;
- refreshed release-gate evidence before any possible future publication.

## Known limitations and non-claims

This candidate does not claim:

- production readiness;
- security audit completion;
- safe direct public-internet exposure;
- broad compatibility with every GnuCash Desktop version or every backend;
- PostgreSQL, MySQL, MariaDB, XML-book, or arbitrary real-world-book compatibility;
- hosted SaaS readiness;
- collaborative accounting, family-wallet positioning, or real-time multi-user editing;
- account, transaction, invoice, bill, customer, vendor, scheduled-transaction editing, CSV/OFX import, or banking integrations;
- safe production write mode for real books;
- production scalability from the synthetic Phase 120 benchmark.

Compatibility evidence remains intentionally narrow: committed synthetic/disposable SQLite fixtures, copied/disposable metadata procedures, safe local tooling probes, and one redacted copied personal-book dogfood pass from the already published `v0.1.2-readonly` cycle. Users must test their own copied book before relying on the app for regular read-only browsing.

## Upgrade notes from v0.1.2-readonly

1. Back up app metadata and any copied test books used with the app.
2. Review `.env.example` and keep `GNUCASH_WRITES_ENABLED=false`.
3. If a later phase explicitly publishes `v0.1.3-readonly`, check out that tag only after confirming the GitHub pre-release exists.
4. Rebuild/restart Docker Compose.
5. Run `/api/health`, login, dashboard, accounts, books, scheduled awareness, transactions, account detail, transaction detail, CSV export, and disabled-write checks on disposable or copied data before regular use.
6. Keep `.env`, app DBs, GnuCash books, backups, real financial exports/screenshots, secrets, tokens, keys, and certs out of git.
