# v0.1.1-readonly Release-Prep Checklist

> Status: prepared in Phase 97. This checklist separates completed evidence, required future release-gate checks, and publication steps that are intentionally not authorized in Phase 97.

## 1. Candidate scope

Status: prepared, not published.

- Release candidate name: `v0.1.1-readonly`.
- Release type: conservative pre-alpha read-only maintenance candidate after `v0.1.0-readonly`.
- MVP baseline remains: one self-hosted installation, one local admin user, one default configured GnuCash book, read-only access.
- GnuCash Desktop remains the authoritative editor.
- Multi-book wording remains about independent accessible books, not collaborative accounting.
- Controlled-write code remains experimental post-MVP work and disabled by default.
- Required default posture remains:

```text
GNUCASH_WRITES_ENABLED=false
```

## 2. Completed evidence from Phases 95 and 96

Already completed before this release-prep artifact:

- Phase 95 fixed GitHub #39, the CSV export row-count/header mismatch above the historical 500-row service clamp.

- Phase 95 targeted synthetic benchmark returned 1,000 CSV data rows with `csv_limit=10000`, `csv_total=1000`, and `truncated=False`.
- Phase 96 generated synthetic large-book benchmark returned 1,000 CSV data rows with `csv_limit=10000`, `csv_total=1000`, `truncated=False`, `csv_expected_body_rows=1000`, and `csv_body_matches_expected=True`.
- Phase 96 frontend copy check confirmed CSV export helper text describes export as read-only, filtered, capped at 10,000 rows, synchronous, and potentially requiring narrower filters.
- GitHub #39 is closed based on synthetic/disposable evidence.
- No real/private data was committed by the Phase 95/96 evidence.
- No `v0.1.1-readonly` tag or release was published by Phases 95/96.

## 6. Known limitations and open issues

- GitHub #38 remains open and blocked until a safe copied personal GnuCash SQL book is available outside git for local-only dogfood. Do not claim personal-book dogfood success.
- GitHub #22 remains relevant for broader compatibility evidence; current evidence is intentionally narrow.
- CORS/deployment hardening remains conservative: do not expose early deployments directly to the public internet.
- CSV export remains synchronous and capped at 10,000 rows; this maintenance candidate fixes row/header consistency, not async export architecture.
- Russian localization remains incomplete and English remains canonical.
- Controlled writes remain post-MVP/experimental and disabled by default; no write-mode feature should be release-marketed as safe for production books.

## 7. Safety checklist for future publish phase

Before publication, re-confirm:

- `GNUCASH_WRITES_ENABLED=false` remains the default.
- Release notes say pre-alpha and read-only by default.
- Release notes say not production-ready and not security-audited.
- Release notes tell users to test disposable/copy books first and keep backups.
- Release notes do not claim broad GnuCash compatibility or personal-book dogfood success.
- No tag/release is created until the release gate says ready and the publish phase is explicitly authorized.
- No real/private financial data, GnuCash books, `.env`, app DBs, backups, screenshots, exports, secrets, tokens, certs, or keys are committed.
