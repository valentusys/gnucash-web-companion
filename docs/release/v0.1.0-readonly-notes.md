# v0.1.0-readonly Release Notes

> Drafted in Phase 79 as a conservative release artifact. This document does not publish a git tag or GitHub release by itself.

## Status

`v0.1.0-readonly` is a pre-alpha, read-only-by-default milestone for cautious self-hosted testing of existing GnuCash SQL books through a browser.

It is not production-ready, not security-audited, and not a hosted finance service. Test only with disposable or copied books first, keep backups, and do not expose early deployments directly to the public internet.

## What this release is for

This release is intended for users who already use GnuCash and want browser/mobile read-only visibility into a configured GnuCash SQL book while keeping GnuCash Desktop as the authoritative editor.

MVP baseline:

- one self-hosted installation;
- one local admin user;
- one default configured GnuCash SQL book;
- read-only access to accounts, transactions, dashboard/report views, and CSV export.

## Included read-only capabilities

- Local admin authentication with httpOnly-cookie session handling.
- Separate application metadata DB for users, book registry/access metadata, and audit placeholders.
- Backend-only GnuCash access through service layers using piecash.
- Account hierarchy and account detail browsing.
- Transaction list, detail pages, pagination, search/filtering, and read-only CSV export with filter parity.
- Basic dashboard/report views with documented base-currency limitations.
- Multi-currency handling that does not fake conversion.
- Read-only book switcher foundation for already-accessible independent books.
- Persistent UI messaging that the application is read-only by default.
- Docker Compose/Caddy self-host deployment scaffold.
- Safe health/startup diagnostics and troubleshooting docs.
- Runtime smoke/dogfood evidence recorded on copied/disposable data in Phases 77 and 78.

## Explicit non-goals and limitations

This release does not provide:

- production-readiness or security-audited guarantees;
- hosted SaaS readiness;
- default-enabled writes;
- safe write mode for real books;
- account, transaction, invoice, bill, customer, vendor, or scheduled-transaction editing as part of v0.1;
- CSV/OFX import or banking integrations;
- direct SQL writes to GnuCash books;
- collaborative accounting, family-wallet positioning, or real-time multi-user editing;
- a replacement for GnuCash Desktop;
- broad compatibility guarantees for all GnuCash Desktop versions;
- PostgreSQL, MySQL, MariaDB, XML-book, or arbitrary real-world-book compatibility guarantees.

Controlled-write code may exist in the repository as experimental post-MVP work, but it is disabled by default and outside the v0.1 read-only release scope.

```text
GNUCASH_WRITES_ENABLED=false
```

Keep that setting unless you are deliberately testing post-MVP write code on disposable data with backups.

## Safety requirements for testers

Before trying this release:

1. Use a disposable fixture or a copied GnuCash SQL book, never your only/original book.
2. Keep tested backups of your original GnuCash data.
3. Keep `.env`, app DBs, copied books, backups, exports, screenshots with real financial data, secrets, tokens, keys, and certs out of git.
4. Keep `GNUCASH_WRITES_ENABLED=false` for v0.1 read-only testing.
5. Run locally, on a trusted LAN, or behind VPN; do not expose the app directly to the public internet.
6. Verify `/api/health`, login, dashboard, accounts, transactions, transaction detail, CSV export, and hidden/blocked write entry points before regular use.

## Compatibility scope

Validated release evidence is intentionally narrow:

- automated tests use committed synthetic/disposable GnuCash SQLite fixtures;
- Phase 77 API dogfood used a copied/disposable SQL fixture and verified read-only API flows plus disabled-write probes;
- Phase 78 browser dogfood used a copied/disposable SQL fixture through Docker/Caddy and verified login, dashboard, accounts, account detail, transactions, transaction detail, CSV export, hidden write UI, and disabled write probes.

Users must test their own copied book before relying on the app for regular read-only browsing.

## Upgrade notes from v0.0.2-prealpha

1. Back up app metadata and any copied test books used with the app.
2. Review `.env.example` for changed settings.
3. Keep `GNUCASH_WRITES_ENABLED=false`.
4. Rebuild/restart Docker Compose after checking out the eventual release tag.
5. Run health checks and the read-only smoke script.
6. Manually verify the UI flows before broader use.

No tag or GitHub release is published by this document. Publication must be a separate explicit step after the final release gate is accepted.
