Date: 2026-05-21

## Summary

`v0.2.8-writealpha` is a conservative pre-alpha write-alpha release candidate for the Cycle 3 maintainer copied-book dogfood package after `v0.2.7-writealpha`.

Phase 260 does not publish a tag or GitHub release. It records that the synthetic copied-book package is strong enough to prepare release-candidate artifacts, while owner copied-book dogfood remains dry-run-only and may still be pending.

## What changed since `v0.2.7-writealpha`

- A maintainer copied-book dogfood packet was added with dry-run first, original/only-copy books forbidden, outside-git copied/restorable targets required, independent backups required, optional mutation limited to one CREATE after review, PATCH deferred, DELETE prohibited unless separately authorized for a write-alpha-created test transaction, redacted evidence, restore proof, cleanup, and reset to `GNUCASH_WRITES_ENABLED=false`.
- A local-only copied-book dogfood wrapper was added with explicit `--dry-run` and `--create-one` modes, required confirmations, preflight, pre-step backup, redacted evidence, unsafe-path rejection, and default-disabled reset proof.
- Transaction create/write-alpha UI warnings were strengthened for maintainer copied-book create-only dogfood: copied/restorable outside-git test book only, original untouched, dry-run first, at most one CREATE test transaction, independent backup plus restore plan, audit/app-backup/lock evidence, and no production use.
- A best-effort compatibility harness was added for post-mutation copied/disposable dogfood. It opens the copied target read-only with piecash, optionally runs already-available `gnucash-cli`, records `pass`/`blocked`/`fail`, and treats missing Desktop/CLI tooling as a blocker rather than compatibility evidence.
- A restore verification harness was added for copied-book dogfood. It restores only an outside-git copied working book from an outside-git pre-mutation backup, verifies checksum/read-back state, can run an optional read-only web/API probe, and records redacted evidence.
- The full maintainer copied-book package was rehearsed on synthetic/disposable fixture copies: dry-run passed, create-one passed through Docker/Caddy with read-back and backup/audit/lock evidence, restore verification passed, temporary Debian `gnucash-cli` report probing passed, and reset default-disabled API smoke verified validate/create/PATCH/DELETE 403 probes.
- The owner copied-book decision gate concluded that the next reasonable owner ask is copied-book dry-run only. CREATE-one is not the immediate owner ask and can be considered only after owner dry-run evidence is reviewed.

## Safety boundaries

- `GNUCASH_WRITES_ENABLED=false` remains the default.
- Write-alpha execution still requires explicit local enablement and `APP_ENV=test`.
- Evidence for this candidate is synthetic/disposable fixture evidence plus release-candidate documentation only. No owner/private/original/only-copy book was used or requested.
- Owner copied-book dogfood may still be pending. The approved next owner step is dry-run only, not CREATE-one.
- No real/private or only-copy write safety is claimed.
- No production readiness, stable release status, security audit, hosted SaaS readiness, public-internet safety, direct public-internet deployment recommendation, banking integration, CSV/OFX import, collaborative accounting, production disaster-recovery, or broad GnuCash Desktop/backend compatibility is claimed.
- No package, binary artifact, Docker image, production deployment, real/private book, app DB, backup artifact, `.env`, screenshot/export, token, key, cert, raw private path, account name, memo, amount, or private financial artifact is included.
