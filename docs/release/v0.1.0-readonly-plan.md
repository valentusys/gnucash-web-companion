# v0.1.0-readonly Release Plan

> Status: planning artifact created in Phase 56. This is not a release approval and does not publish a tag or GitHub release.

## Purpose

`v0.1.0-readonly` is intended to be the first deliberately planned read-only MVP milestone for private/self-hosted testing of existing GnuCash SQL books through a browser.

The release must remain conservative:

- read-only by default;
- one installation, one local admin user, one default configured GnuCash book as the MVP baseline;
- GnuCash Desktop remains the authoritative editor;
- test with disposable or copied books first;
- no production-readiness or audited-security claim;
- controlled-write code, if present, remains experimental post-MVP and disabled by default with `GNUCASH_WRITES_ENABLED=false`.

## Release decision

Phase 55 audit verdict: ready to prepare v0.1 read-only.

That verdict allows this plan/checklist to exist. It does not approve publishing `v0.1.0-readonly`. A future explicit release-gate phase must decide whether to publish.

## Included features

The v0.1 read-only milestone may include only the current read-only and safety/governance scope:

1. Authentication and local admin session flow using httpOnly cookies.
2. Separate app metadata database for users, book registry/access metadata, and audit placeholders.
3. Read-only access to configured GnuCash SQL books through backend service layers.
4. Account tree and account detail browsing.
5. Transaction list, transaction detail, pagination, and documented search/filter behavior.
6. Read-only transaction CSV export with documented filter parity and row cap.
7. Basic dashboard/report views using documented base-currency limitations.
8. Multi-currency limitation handling without fake conversion.
9. Read-only book switcher foundation for already-accessible independent books.
10. Persistent read-only-by-default UI safety messaging.
11. Docker Compose deployment scaffold with Caddy reverse proxy.
12. Safe health/startup diagnostics and troubleshooting documentation.
13. Personal dogfood/read-only smoke documentation using copied/disposable books.
14. Automated read-only API smoke script for local Docker deployments.
15. Conservative public documentation, changelog, release checklist, and audit trail.

## Excluded features

These are explicitly excluded from `v0.1.0-readonly`:

- default-enabled writes;
- any claim that controlled writes are production-safe;
- new write capabilities or expanded write scope;
- account, invoice, bill, customer, vendor, or scheduled-transaction editing;
- CSV/OFX import or banking integrations;
- direct SQL writes to GnuCash books;
- hosted SaaS positioning;
- collaborative accounting or family-wallet baseline positioning;
- book upload/management UI as a v0.1 requirement;
- broad GnuCash version compatibility guarantee;
- PostgreSQL/MySQL/MariaDB/XML compatibility guarantee;
- production-readiness, audited-security, or public-internet exposure claims.

## Minimum test commands

Before any `v0.1.0-readonly` release gate, run from repository root unless noted:

```bash
cd apps/api && pytest -q
cd apps/web && npm run check && npm run test:auth-routes && npm run build
JWT_SECRET=dummy-validation-secret APP_ADMIN_PASSWORD=dummy docker compose config --quiet
git diff --check
```

Recommended targeted safety subset:

```bash
cd apps/api && pytest -q tests/test_transaction_writes.py::TestWritesDisabledByDefault
```

## Dogfood requirements

Before publishing `v0.1.0-readonly`, complete and record a clean dogfood/smoke pass using only copied or disposable data:

1. Start from a clean clone or clean checkout.
2. Create `.env` from `.env.example` without committing it.
3. Use a disposable or copied GnuCash SQL book under `data/books/`.
4. Confirm `GNUCASH_WRITES_ENABLED=false`.
5. Start Docker Compose locally or on a LAN/VPN-only host.
6. Run the automated smoke script:

```bash
SMOKE_API_BASE_URL=http://localhost:8080/api \
SMOKE_ADMIN_USERNAME=admin \
SMOKE_ADMIN_PASSWORD='<local-admin-password>' \
python3 scripts/smoke/read-only-api-smoke.py
```

7. Manually verify login, dashboard, accounts, account detail, transactions, transaction detail, CSV export, book switcher behavior if multiple accessible books exist, and hidden/blocked write entry points while writes are disabled.
8. Record limitations or failures in the release-gate handoff.
9. Do not commit `.env`, app DBs, copied books, backups, screenshots from real data, or CSV exports from real data.

## Compatibility scope

The v0.1 release may claim only the compatibility actually validated by tests and docs:

- GnuCash SQL SQLite fixture paths used by the automated test suite.
- Generated/committed synthetic disposable fixtures only.
- Backend read-only access through piecash service layers.

The release must not claim broad compatibility with:

- all GnuCash Desktop versions;
- PostgreSQL/MySQL/MariaDB backends;
- XML books;
- arbitrary real-world book features;
- production deployment environments.

Users must be told to test a copied book first and keep backups.

## Upgrade path from v0.0.2-prealpha

`v0.1.0-readonly` should be treated as a normal source upgrade from `v0.0.2-prealpha`:

1. Stop the existing deployment.
2. Back up the app metadata DB and any copied GnuCash books used with the app.
3. Fetch the new tag after it is published.
4. Review `.env.example` for changed environment variables.
5. Keep `GNUCASH_WRITES_ENABLED=false` unless explicitly testing post-MVP write mode on disposable data.
6. Rebuild/restart Docker Compose.
7. Run health checks and the read-only smoke script.
8. Verify UI screens before using the deployment for regular read-only browsing.

No automatic database migration guarantee should be claimed beyond what has been tested in the release gate.

## Release blockers

Do not publish `v0.1.0-readonly` if any of these remain true:

1. Backend tests fail.
2. Frontend check, auth-route test, or build fails.
3. Docker Compose config validation fails.
4. Disabled-write regression tests fail or `GNUCASH_WRITES_ENABLED=false` is no longer the default.
5. Any write route can validate/create/patch while writes are disabled.
6. Documentation claims production readiness, audited security, broad compatibility, safe write mode, SaaS readiness, or collaborative accounting.
7. A real GnuCash book, `.env`, app DB, backup, secret, key, token, cert, real screenshot, or real financial export is staged/tracked.
8. Release notes do not clearly say read-only by default and not production-ready.
9. Clean local Docker/runtime smoke with copied/disposable data has not been attempted or its failure is not explicitly accepted by the release gate.
10. A dedicated release-gate audit has not been completed.

## Rollback plan

If a v0.1 test deployment fails:

1. Stop the deployment.
2. Preserve logs without secrets for debugging.
3. Restore the previous app metadata DB backup if needed.
4. Restore copied GnuCash book files from backup if they were changed outside the app.
5. Check out the previous known-good tag, currently `v0.0.2-prealpha`, or the previous deployment commit.
6. Rebuild/restart Docker Compose.
7. Run `/api/health` and the read-only smoke script.
8. Keep the failed v0.1 deployment private until the release-gate issue is resolved.
