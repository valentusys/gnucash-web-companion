## Status

`v0.2.1-writealpha` is a conservative pre-alpha write-alpha maintenance pre-release after the published `v0.2.0-writealpha` experimental pre-release and the published `v0.1.7-readonly` read-only pre-release.

This candidate remains pre-alpha, experimental, not production-ready, and not security-audited. It must not be exposed directly to the public internet. It must not be used for write-alpha operations against real/private books or the only copy of a GnuCash book.

The application remains read-only by default:

```text
GNUCASH_WRITES_ENABLED=false
```

Even when an operator explicitly enables write mode for local dogfood, backend write-alpha routes still require:

```text
APP_ENV=test
```

The new write-alpha evidence for this candidate is copied/disposable or synthetic fixture evidence only. It is not evidence that real/private-book writes are safe.

## What changed since v0.2.0-writealpha

The release summarizes Phases 173–182:

- Phase 173 — added an executable local-only copied-book write-alpha dogfood runbook and a safe preflight interface outline; no write dogfood was run.
- Phase 174 — implemented a stricter dry-run preflight harness that fails closed for unsafe source/runtime/backup paths and emits only redacted metadata.
- Phase 175 — ran one controlled create dogfood on a synthetic/disposable copied book with explicit `APP_ENV=test` and local-only `GNUCASH_WRITES_ENABLED=true`; backup, audit, read-back, validation failures, lock release, restore, and default-disabled return were verified.
- Phase 176 — verified the disposable mutated book with GnuCash CLI 4.13 inside a temporary Debian container. This is narrow tooling evidence only, not broad Desktop compatibility.
- Phase 177 — ran a backup/restore drill for the disposable write-alpha create path and verified the restored copy returned to default read-only smoke with disabled write probes.
- Phase 178 — improved write-alpha frontend guardrails and safe error handling so the disposable/test-copy boundary is clearer and raw path-like backend details are not rendered in write forms.
- Phase 179 — hardened backend write-alpha error handling for lock contention and path-like write errors while preserving backup/audit evidence for post-backup failures.
- Phase 180 — reran combined default-read-only Docker/Caddy dogfood plus a separate explicit disposable write-alpha create smoke; default write-disabled API/browser flows passed, validate/create/PATCH/DELETE probes returned 403 under default false, and the write-alpha smoke remained explicit/local/synthetic.
- Phase 181 — prepared this final release-readiness gate and publication decision artifact without publishing.
- Phase 182 — re-ran a fresh pre-publish gate on `main`, confirmed tag/release absence and green CI for the exact release commit, then published the annotated tag and GitHub pre-release.

## Candidate scope

The write-alpha surface remains unchanged from `v0.2.0-writealpha`:

- create transaction;
- PATCH transaction metadata/split memo scope as implemented by the write service;
- DELETE transaction.

All write-alpha routes must remain disabled unless both gates are satisfied:

```text
GNUCASH_WRITES_ENABLED=true
APP_ENV=test
```

The default documented and configured posture remains:

```text
GNUCASH_WRITES_ENABLED=false
```

## Safety boundaries and non-claims

This candidate does not claim:

- production readiness;
- security audit completion;
- safe direct public-internet exposure;
- safe write mode for real/private GnuCash books;
- safe write mode for the only copy of any book;
- broad compatibility with every GnuCash Desktop version or every backend;
- PostgreSQL, MySQL, MariaDB, XML-book, or arbitrary real-world-book compatibility;
- hosted SaaS readiness;
- collaborative accounting, family-wallet positioning, or real-time multi-user editing;
- invoice, bill, customer, vendor, scheduled-transaction editing;
- account editing, recurring transaction editing, CSV/OFX import, or banking integrations.

Use only synthetic/disposable fixtures or copied books that can be restored or deleted. Keep backups. Keep `.env`, app DBs, GnuCash books, backups, real financial exports/screenshots, secrets, tokens, keys, and certs out of git.

## Upgrade notes from v0.2.0-writealpha

1. Treat this as an experimental pre-alpha write-alpha pre-release, not as production-ready software.
2. Keep `GNUCASH_WRITES_ENABLED=false` unless intentionally running synthetic/disposable write-alpha tests.
3. Never enable write-alpha routes outside a disposable/test environment; write execution still requires `APP_ENV=test`.
4. Rebuild/restart Docker Compose after updating.
5. Run `/api/health`, login, dashboard, accounts, books, scheduled awareness, transactions, account detail, transaction detail, CSV export, and disabled-write checks on disposable or copied data before any regular read-only use.
6. If experimenting with writes, use only synthetic/disposable fixtures or restorable copied test books and follow `docs/dogfood/write-alpha-copied-book-runbook.md`, `docs/write-alpha-maintainer-checklist.md`, and `docs/write-alpha-recovery-procedure.md`.
