# v0.1.1-readonly Draft Release Notes

> Draft prepared in Phase 97. This document is a release-prep artifact only: it does not create a git tag, publish a GitHub release, or authorize publication.

## Status

`v0.1.1-readonly` is intended as a conservative pre-alpha maintenance release candidate for the already published `v0.1.0-readonly` read-only milestone.

The project remains read-only by default. GnuCash Desktop remains the authoritative editor. This project is not production-ready, not security-audited, and not a hosted financial service. Test with disposable fixtures or copied GnuCash SQL books first, keep backups, and do not expose early deployments directly to the public internet.

Controlled-write code may exist in the repository as experimental post-MVP work, but it is outside the read-only maintenance release scope and remains disabled by default:

```text
GNUCASH_WRITES_ENABLED=false
```

## Maintenance summary since v0.1.0-readonly

The candidate maintenance value is focused on safer read-only operation, clearer export behavior, and better supporting evidence. Notable post-`v0.1.0-readonly` work includes:

- Phase 81: default-book seed logs were redacted so startup logs no longer expose full configured book paths or connection URI details.
- Phase 82: read-only multi-book access-boundary regression coverage was expanded for archived and unauthorized books across route families.
- Phase 83: frontend money-display decisions were hardened to avoid using `Number()` for money-string display logic.
- Phase 84: CSV export response headers and frontend proxy forwarding were added for export limit, total, truncation, and timeout policy metadata.
- Phase 86: a redacted copied-book preflight helper was added for future safe personal-book dogfood attempts.
- Phase 87 through Phase 89: synthetic benchmark coverage was expanded for large books, many-splits transactions, and dashboard aggregate paths.
- Phase 90: transaction filter UI now summarizes active filters and states that the same filters apply to the read-only list and CSV export.
- Phase 91: a read-only `/books` metadata page was added for accessible configured books.
- Phase 92: safe GnuCash compatibility metadata collection was added for copied/disposable SQLite books without exposing private paths or financial details.
- Phase 93: a narrow Russian localization slice was added while keeping English canonical and translation status honest.
- Phase 95: GitHub #39 was fixed: read-only CSV export now fetches up to the documented 10,000-row export cap instead of inheriting the historical 500-row list-service clamp.
- Phase 96: the Phase 95 CSV export fix was confirmed through the generated synthetic large-book benchmark path: a 1,000-transaction synthetic run returned 1,000 CSV data rows with `csv_limit=10000`, `csv_total=1000`, `truncated=False`, `csv_expected_body_rows=1000`, and `csv_body_matches_expected=True`.

## CSV export fix and evidence

GitHub #39 is fixed and closed based on synthetic/disposable evidence:

- Regression coverage proves a 501-row synthetic export returns 501 CSV data rows with `X-CSV-Export-Limit: 10000`, `X-CSV-Export-Total: 501`, and `X-CSV-Export-Truncated: false`.
- The Phase 95 targeted synthetic benchmark returned 1,000 CSV data rows with `csv_limit=10000`, `csv_total=1000`, and `truncated=False`.
- The Phase 96 generated large-book benchmark recorded body-row consistency fields and confirmed `csv_body_matches_expected=True` for 1,000 synthetic transactions.

This is correctness evidence for the tested read-only CSV export path. It is not a production performance claim. CSV export remains synchronous and capped at 10,000 rows; users may still need narrower filters if an export times out or is truncated.

## Known limitations and non-claims

This draft release still does not claim:

- production readiness;
- security audit completion;
- safe direct public-internet exposure;
- broad compatibility with every GnuCash Desktop version or every backend;
- PostgreSQL, MySQL, MariaDB, XML-book, or arbitrary real-world-book compatibility;
- successful personal-book dogfood for the post-v0.1 maintenance changes;
- hosted SaaS readiness;
- collaborative accounting, family-wallet positioning, or real-time multi-user editing;
- account, transaction, invoice, bill, customer, vendor, scheduled-transaction editing, CSV/OFX import, or banking integrations as part of this read-only maintenance candidate;
- safe production write mode for real books.

GitHub #38 remains open and blocked until a safe copied personal GnuCash SQL book is available outside git for a local-only dogfood rerun. Do not claim personal-book dogfood success for `v0.1.1-readonly` unless a later phase records that evidence without committing private data.

Compatibility evidence remains intentionally narrow: committed synthetic/disposable SQLite fixtures, copied/disposable dogfood evidence from earlier phases, and safe metadata collection procedures. Users must test their own copied book before relying on the app for regular read-only browsing.

## Upgrade notes from v0.1.0-readonly

1. Back up app metadata and any copied test books used with the app.
2. Review `.env.example` and keep `GNUCASH_WRITES_ENABLED=false`.
3. Check out the eventual `v0.1.1-readonly` tag only after it is explicitly published by a later authorized phase.
4. Rebuild/restart Docker Compose.
5. Run `/api/health`, login, dashboard, accounts, transactions, transaction detail, CSV export, and disabled-write checks on disposable or copied data before regular use.
6. Keep `.env`, app DBs, GnuCash books, backups, real financial exports/screenshots, secrets, tokens, keys, and certs out of git.
