Date: 2026-05-21
Phase: 231
Release: `v0.2.5-writealpha`
Publication status: `PUBLISHED AS GITHUB PRE-RELEASE`

## Summary

`v0.2.5-writealpha` is a conservative pre-alpha write-alpha maintenance pre-release. It is published only after the Cycle 3 release gate rechecked the evidence from Phases 222–230, local backend/frontend/Docker checks, public status guard, sensitive tracked-file hygiene, candidate tag/release absence, and GitHub Actions on the exact Phase 231 release/status commit.

This release keeps writes disabled by default. Experimental write-alpha routes remain constrained to explicit local enablement plus the existing backend `APP_ENV=test` gate and synthetic/disposable or copied test-book evidence only.

## What changed since `v0.2.4-writealpha`

- Reconciled the previous Phase 220 DELETE backup-count blocker: backup artifact naming now uses microsecond timestamps, deterministic suffix fallback, and exclusive-create copy so rapid synthetic create/PATCH/DELETE backup evidence cannot silently overwrite earlier artifacts.
- Hardened write-alpha backup/audit evidence: tests and helpers prove unique readable backups, backup-bearing audit correlation, redacted operator evidence, safe backup-failure/no-mutation behavior, and app-metadata-only audit-summary review.
- Re-ran bounded synthetic/disposable write-alpha evidence after remediation: create, PATCH, and DELETE each passed with matching backup/audit evidence; DELETE restore/read-back proof passed; locks were verified stale-released/not active; default-disabled reset passed.
- Rechecked default read-only behavior: Docker/Caddy API and browser dogfood passed with `GNUCASH_WRITES_ENABLED=false`, hidden write UI, disabled validate/create/PATCH/DELETE probes returning 403, mobile and desktop viewports, and cleanup/no-artifact checks.
- Rechecked fresh-clone and upgrade paths with disabled writes: current `main` fresh clone and synthetic upgrade from `v0.2.4-writealpha` runtime state passed without enabling write mode.
- Refreshed public status/release-doc drift guards so README, README.ru, CHANGELOG, PROJECT_STATUS, docs/ROADMAP, and release-support docs agree on the Phase 231 publication posture.

## Safety boundaries

- `GNUCASH_WRITES_ENABLED=false` remains the default.
- Write-alpha execution still requires explicit local enablement and `APP_ENV=test`.
- Evidence remains synthetic/disposable or copied-test-book only.
- No real/private-book or only-copy write safety is claimed.
- No production readiness, stable release status, security audit, hosted SaaS readiness, public-internet safety, direct public-internet deployment recommendation, banking integration, CSV/OFX import, collaborative accounting, or broad GnuCash Desktop/backend compatibility is claimed.
- No package, binary artifact, Docker image, production deployment, real/private book, app DB, backup artifact, `.env`, screenshot/export, token, key, cert, raw private path, account name, memo, amount, or private financial artifact is published by this release.
