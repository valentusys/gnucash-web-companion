# v0.1.0-readonly Release Checklist

> Status: planning checklist created in Phase 56. Do not use this document as approval to publish. A later explicit release phase and release-gate audit are required.

## 1. Scope confirmation

- [ ] Release name is `v0.1.0-readonly`.
- [ ] Release is described as read-only by default.
- [ ] GnuCash Desktop is described as the authoritative editor.
- [ ] The MVP baseline is one installation, one local admin user, and one default configured GnuCash book.
- [ ] Any multi-book language is framed as independent accessible books, not collaborative accounting.
- [ ] Controlled-write code is described as experimental post-MVP and disabled by default.
- [ ] `GNUCASH_WRITES_ENABLED=false` remains the documented/configured default.

## 2. Explicit non-goals verified

- [ ] No default-enabled writes.
- [ ] No new write capability added for this release.
- [ ] No account/invoice/bill/customer/vendor/scheduled-transaction editing.
- [ ] No CSV/OFX import.
- [ ] No banking integration.
- [ ] No hosted SaaS positioning.
- [ ] No collaborative accounting or family-wallet baseline positioning.
- [ ] No production-readiness or audited-security claim.
- [ ] No broad GnuCash-version compatibility guarantee.

## 3. Documentation readiness

- [ ] README current status matches the intended v0.1 release posture.
- [ ] CHANGELOG has a v0.1 entry or release-facing Unreleased summary.
- [ ] Release notes for `v0.1.0-readonly` exist and are conservative.
- [ ] `docs/release/v0.1.0-readonly-plan.md` is still accurate.
- [ ] This checklist is complete or has explicit accepted exceptions.
- [ ] Safety docs still tell users to test copied/disposable books first.
- [ ] Deployment docs warn against direct public-internet exposure.
- [ ] Troubleshooting docs avoid asking users to share secrets or real financial data.
- [ ] Compatibility docs clearly limit what has been validated.

## 4. Automated checks

Run from repository root unless noted.

- [ ] Backend tests pass:

```bash
cd apps/api && pytest -q
```

- [ ] Disabled-write safety subset passes:

```bash
cd apps/api && pytest -q tests/test_transaction_writes.py::TestWritesDisabledByDefault
```

- [ ] Frontend check passes:

```bash
cd apps/web && npm run check
```

- [ ] Frontend auth-route/static safety checks pass:

```bash
cd apps/web && npm run test:auth-routes
```

- [ ] Frontend production build passes:

```bash
cd apps/web && npm run build
```

- [ ] Docker Compose config validates:

```bash
JWT_SECRET=dummy-validation-secret APP_ADMIN_PASSWORD=dummy docker compose config --quiet
```

- [ ] Whitespace diff check passes:

```bash
git diff --check
```

## 5. Runtime smoke / dogfood gate

Use only copied or disposable GnuCash data.

- [ ] Clean checkout or clean deployment directory used.
- [ ] `.env` created locally and not committed.
- [ ] `JWT_SECRET` is not the placeholder.
- [ ] Admin password/hash is locally set and not committed.
- [ ] `GNUCASH_WRITES_ENABLED=false` confirmed.
- [ ] Disposable/copied SQL book placed under `data/books/`.
- [ ] Docker Compose starts successfully.
- [ ] `/api/health` returns non-sensitive health data.
- [ ] Automated smoke script passes:

```bash
SMOKE_API_BASE_URL=http://localhost:8080/api \
SMOKE_ADMIN_USERNAME=admin \
SMOKE_ADMIN_PASSWORD='<local-admin-password>' \
python3 scripts/smoke/read-only-api-smoke.py
```

- [ ] Manual login works.
- [ ] Dashboard loads.
- [ ] Accounts tree loads.
- [ ] Account detail loads.
- [ ] Transactions list loads.
- [ ] Transaction detail loads.
- [ ] CSV export downloads expected copied/disposable-book data.
- [ ] Write entry points are hidden or blocked while writes are disabled.
- [ ] No screenshots/exports from real data are committed.

## 6. Compatibility gate

- [ ] Synthetic fixture tests pass.
- [ ] Compatibility docs name the tested SQLite fixture scope.
- [ ] Release notes do not claim PostgreSQL/MySQL/MariaDB/XML support.
- [ ] Release notes do not claim support for all GnuCash Desktop versions.
- [ ] Issue #22 is either explicitly kept open or updated with a justified release decision.

## 7. Security/sensitive-data hygiene

- [ ] `.env` is not tracked.
- [ ] App metadata DB files are not tracked.
- [ ] Real GnuCash books are not tracked.
- [ ] Backups are not tracked.
- [ ] Secrets, tokens, keys, certs, and credentials are not tracked.
- [ ] Real screenshots are not tracked.
- [ ] Real CSV/financial exports are not tracked.
- [ ] Auth token storage remains httpOnly-cookie based, not localStorage/sessionStorage.
- [ ] No telemetry was added.

## 8. GitHub/project hygiene

- [ ] Open issues are reviewed before release.
- [ ] Issues #11, #12, #13, #17, and #22 have explicit v0.1 in/out decisions.
- [ ] A dedicated v0.1 release-gate audit artifact exists under `docs/audits/`.
- [ ] GitHub Actions CI is green for the release commit, or any limitation is explicitly accepted by the release gate.
- [ ] The release commit has a clean working tree before tagging.

## 9. Tag/release publication gate

Do not run these commands until a later explicit release phase says to publish and every required gate is satisfied:

```bash
git tag -a v0.1.0-readonly -m "v0.1.0-readonly"
git push origin v0.1.0-readonly
gh release create v0.1.0-readonly \
  --title "v0.1.0-readonly" \
  --notes-file docs/release/v0.1.0-readonly-notes.md \
  --prerelease
```

Publication is blocked if the release notes file does not exist, checks are failing, the release-gate audit is missing, or the working tree is dirty.
