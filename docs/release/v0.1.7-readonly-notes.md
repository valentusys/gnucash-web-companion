# v0.1.7-readonly Release Notes

> Prepared and published in Phase 171 as an authorized read-only maintenance GitHub pre-release.
>
> Publication status: published as a GitHub pre-release. No package, binary artifact, Docker image, or production deployment was created.

## Status

`v0.1.7-readonly` is a conservative pre-alpha read-only maintenance pre-release after the published `v0.1.6-readonly` read-only pre-release and the separately published `v0.2.0-writealpha` experimental pre-release.

The project remains read-only by default. GnuCash Desktop remains the authoritative editor. This project is not production-ready, not security-audited, and not a hosted financial service. Test with disposable fixtures or copied GnuCash SQL books first, keep backups, and do not expose early deployments directly to the public internet.

Controlled-write code may exist in the repository as experimental post-MVP/write-alpha work, but it is outside this read-only maintenance release and remains disabled by default:

```text
GNUCASH_WRITES_ENABLED=false
```

## What changed since v0.1.6-readonly

This release summarizes read-only maintenance, operator UX, localization, and release-candidate dogfood work completed after `v0.1.6-readonly`:

- Phase 162: synchronized the stale post-`v0.1.6-readonly` roadmap baseline and verified the published `v0.1.6-readonly` tag from a fresh Docker checkout with synthetic/disposable data, `GNUCASH_WRITES_ENABLED=false`, API smoke, browser dogfood, disabled validate/create/patch/delete probes, and no raw screenshot/export/backup artifacts.
- Phase 163: moved GitHub #22 compatibility evidence forward with a disposable Debian 12 container probe. GnuCash 4.13 tooling was available in the container, but no safe noninteractive SQLite fixture creation path was identified; no Desktop-generated fixture or broad Desktop/version/backend compatibility claim was added.
- Phase 164: hardened read-only book-context recovery for invalid, stale, or inaccessible selected-book cookies while keeping archived/unauthorized books hidden/blocked and raw `uri_or_path` values out of API/UI.
- Phase 165: added synthetic large-account-tree benchmark evidence and capped deep account-tree indentation to reduce overflow risk without adding account editing, caching, or production scalability claims.
- Phase 166: hardened synchronous read-only CSV export feedback for empty, filtered, capped/truncated, string-amount, no-conversion, and account-scoped parity cases without adding import or background export.
- Phase 167: improved local/LAN auth/session defaults by rejecting mismatched-Origin unsafe SvelteKit app-route requests and aligning the web auth cookie lifetime with the configured JWT expiry, without claiming a production security audit.
- Phase 168: improved first-run and broken-configuration operator UX with safe `/health`, startup, `/login`, `/books`, global-error, and troubleshooting guidance while redacting paths/secrets.
- Phase 169: completed a release-critical Russian localization slice for login/auth/service-configuration and global error guidance without claiming full localization or backend API localization.
- Phase 170: reran full cycle 2 synthetic/disposable Docker/Caddy release-candidate dogfood with `GNUCASH_WRITES_ENABLED=false`; API smoke and browser dogfood passed at 320x720 and 1280x900, including hidden write UI, disabled validate/create/patch/delete write probes, auth-cookie no-readability, no-overflow, and no-artifact checks.
- Phase 171: re-ran the final release gate and prepared this release artifact set for authorized publication if CI remains green.

## Read-only maintenance value

The release is meaningful because it improves the self-hosted read-only operator path and refreshes runtime evidence without expanding write scope:

- published-tag fresh-checkout smoke coverage for the prior read-only release;
- safer selected-book recovery and configured-book access guidance;
- bounded large account-tree usability/performance evidence;
- clearer CSV export feedback and account-scoped export parity;
- stronger local/LAN session/origin behavior and first-run diagnostics;
- broader release-critical Russian localization coverage;
- full synthetic Docker/Caddy API/browser dogfood after the cycle.

## Known limitations and non-claims

This release does not claim:

- production readiness;
- security audit completion;
- safe direct public-internet exposure;
- broad compatibility with every GnuCash Desktop version or every backend;
- PostgreSQL, MySQL, MariaDB, XML-book, or arbitrary real-world-book compatibility;
- hosted SaaS readiness;
- collaborative accounting, family-wallet positioning, or real-time multi-user editing;
- account, transaction, invoice, bill, customer, vendor, scheduled-transaction editing, CSV/OFX import, or banking integrations;
- safe production write mode for real books;
- production scalability or full real-world-book coverage from synthetic dogfood evidence.

Compatibility and dogfood evidence remain intentionally narrow: committed synthetic/disposable SQLite fixtures, disposable-container tooling probes, safe local metadata procedures, previous redacted copied-book dogfood evidence from earlier releases, published-tag fresh-checkout smoke evidence, and Phase 170 synthetic Docker/Caddy release-candidate dogfood. Users must test their own copied book before relying on the app for regular read-only browsing.

## Upgrade notes from v0.1.6-readonly

1. Back up app metadata and any copied test books used with the app.
2. Review `.env.example` and keep `GNUCASH_WRITES_ENABLED=false`.
3. Check out the `v0.1.7-readonly` tag from the GitHub pre-release after publication.
4. Rebuild/restart Docker Compose.
5. Run `/api/health`, login, dashboard, accounts, books, scheduled awareness, transactions, account detail, transaction detail, CSV export, and disabled-write checks on disposable or copied data before regular use.
6. Keep `.env`, app DBs, GnuCash books, backups, real financial exports/screenshots, secrets, tokens, keys, and certs out of git.
