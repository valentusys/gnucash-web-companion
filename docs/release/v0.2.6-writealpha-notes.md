# v0.2.6-writealpha Release-Candidate Notes

Date: 2026-05-21
Phase: 240
Target release: `v0.2.6-writealpha`
Publication status: `RELEASE CANDIDATE ONLY — NOT TAGGED OR PUBLISHED`

## Summary

`v0.2.6-writealpha` is a proposed conservative pre-alpha write-alpha maintenance candidate for the Cycle 1 work after `v0.2.5-writealpha`.

The candidate is release-worthy because Phases 232–239 produced practical operator-safety artifacts for future copied/disposable write-alpha dogfood: public status reconciliation, raw markdown readability, copied-book dogfood runbook, redacted target preflight, redacted evidence schema/helper, write-alpha environment guidance, non-mutating readiness inspection, and synthetic Docker/Caddy no-mutation dry-run evidence.

This document is not a publication artifact. It is a release-candidate draft only. A later release/no-release gate with PM authorization is required before any tag or GitHub pre-release.

## What changed since `v0.2.5-writealpha`

- Public docs were reconciled after `v0.2.5-writealpha` publication so the current write-alpha pre-release state, Phase 231 publication baseline, default-disabled writes, and `APP_ENV=test` gate are consistent.
- README, README.ru, CHANGELOG, and PROJECT_STATUS were reformatted for raw markdown readability without changing safety posture.
- A conservative copied-book write-alpha dogfood runbook was added for future local-only copied/disposable testing. It forbids original and only-copy books, requires outside-git copies, independent backups, one mutation at a time, stop conditions, redacted evidence, restore verification, and reset to disabled writes.
- `scripts/write_alpha_preflight.py` was added as a local-only redacted target preflight. It rejects missing, unreadable, inside-git, unsafe-backup, and unsafe-environment cases before any mutation.
- A redacted dogfood evidence schema and helper were added so future dogfood reports can reject or redact raw paths, amount-like values, memo/account-name fields, and payload-like values before commit.
- `.env.writealpha.example` and write-alpha environment guidance were added as an unsafe-for-real-books operator reference. They require explicit `GNUCASH_WRITES_ENABLED=true` plus `APP_ENV=test` for local write-alpha testing and do not change normal defaults.
- `scripts/write_alpha_readiness.py` and backend helper coverage were added for a redacted, non-mutating readiness inspection path that reports write flag, `APP_ENV=test` gate, backup policy, app DB reachability, default-book read-only openability, and `mutation_performed=false` without constructing the write service.
- A synthetic copied-book Docker/Caddy dry-run was recorded with preflight/readiness, default-disabled API/browser smoke, disabled validate/create/PATCH/DELETE probes returning 403, checksum no-mutation proof, and zero backup/lock/audit-row artifacts.

## Safety boundaries

- `GNUCASH_WRITES_ENABLED=false` remains the default.
- Write-alpha execution still requires explicit local enablement and `APP_ENV=test`.
- Evidence for this candidate is synthetic/disposable only, plus future copied-test-book procedure documentation. No real/private or only-copy write safety is claimed.
- No create/PATCH/DELETE mutation was run in Phase 239; the Cycle 1 dogfood evidence is a no-mutation dry-run.
- No production readiness, stable release status, security audit, hosted SaaS readiness, public-internet safety, direct public-internet deployment recommendation, banking integration, CSV/OFX import, collaborative accounting, or broad GnuCash Desktop/backend compatibility is claimed.
- No package, binary artifact, Docker image, production deployment, real/private book, app DB, backup artifact, `.env`, screenshot/export, token, key, cert, raw private path, account name, memo, amount, or private financial artifact is included.
