> Publication status: published in Phase 191 after the cycle-2 release-readiness gate, green local checks, green GitHub Actions on the exact release commit, and tag/release absence checks.

## Status

`v0.2.2-writealpha` is a conservative pre-alpha write-alpha maintenance pre-release after `v0.2.1-writealpha`.

This release remains experimental, not production-ready, and not security-audited. Do not expose it directly to the public internet. Do not use write-alpha operations against real/private books or the only copy of a GnuCash book.

The application remains read-only by default:

```text
GNUCASH_WRITES_ENABLED=false
```

When write mode is explicitly enabled for local disposable testing, backend write-alpha routes still require:

```text
APP_ENV=test
```

All new write-alpha evidence for this release is synthetic/disposable fixture evidence only. It is not evidence that real/private-book writes are safe.

## What changed since v0.2.1-writealpha

The release summarizes Phases 183–191:

- Phase 183 — added path-safe lock inspection and recovery guidance for active, stale released, unreadable/root-owned, and absent lock states without automatic lock deletion or write-scope expansion.
- Phase 184 — ran one explicit local-only PATCH metadata/split-memo dogfood on a synthetic/disposable runtime copy; read-back, backup, audit, safe missing-transaction behavior, stale/non-active lock evidence, default-disabled reset, and teardown were documented.
- Phase 185 — ran one explicit local-only DELETE dogfood on a synthetic/disposable runtime copy and proved restore from the generated backup in that phase.
- Phase 186 — added a read-only operator audit-summary endpoint/UI for synthetic/disposable write-alpha runs, redacting backup paths, private paths, raw payloads, memos, and amounts.
- Phase 187 — hardened multi-book read-only access and selected-book recovery after write-alpha work; write UI remains hidden by default.
- Phase 188 — strengthened read-only dashboard/reporting correctness for mixed currencies, unknown `XXX` base currency, zero-balance fallback, signed contra balances, Decimal/string amounts, and drilldown URL parity.
- Phase 189 — ran fresh-clone Docker smokes against current public read-only tag, current public write-alpha tag, and current `main`, all with synthetic fixture data and `GNUCASH_WRITES_ENABLED=false`.
- Phase 190 — ran combined cycle-2 release-candidate dogfood: default read-only API/browser smokes and separate explicit local-only create/PATCH/DELETE write-alpha evidence on synthetic/disposable runtime copies. Host-side root-owned runtime readability limited the Phase 190 helper restore/lock finalization checks, so Phase 190 does not add a new restore claim beyond the earlier Phase 185 DELETE restore proof.
- Phase 191 — performed this final release-readiness gate and publication decision.

## Release scope

The write-alpha surface remains unchanged from earlier write-alpha releases:

- create transaction;
- PATCH transaction metadata/split memo scope as implemented by the write service;
- DELETE transaction.

All write-alpha routes must remain disabled unless both gates are satisfied:

```text
GNUCASH_WRITES_ENABLED=true
APP_ENV=test
```

The default documented and configured posture remains:

```text
GNUCASH_WRITES_ENABLED=false
```

## Safety boundaries and non-claims

This release does not claim:

- production readiness;
- security audit completion;
- safe direct public-internet exposure;
- safe write mode for real/private GnuCash books;
- safe write mode for the only copy of any book;
- broad compatibility with every GnuCash Desktop version or every backend;
- PostgreSQL, MySQL, MariaDB, XML-book, or arbitrary real-world-book compatibility;
- hosted SaaS readiness;
- collaborative accounting, family-wallet positioning, or real-time multi-user editing;
- invoice, bill, customer, vendor, scheduled-transaction editing;
- account editing, recurring transaction editing, CSV/OFX import, or banking integrations.

Use only synthetic/disposable fixtures or copied books that can be restored or deleted. Keep backups. Keep `.env`, app DBs, GnuCash books, backups, real financial exports/screenshots, secrets, tokens, keys, and certs out of git.

## Upgrade notes from v0.2.1-writealpha

1. Treat this as an experimental pre-alpha write-alpha pre-release, not production-ready software.
2. Keep `GNUCASH_WRITES_ENABLED=false` unless intentionally running synthetic/disposable write-alpha tests.
3. Never enable write-alpha routes outside a disposable/test environment; write execution still requires `APP_ENV=test`.
4. Rebuild/restart Docker Compose after updating.
5. Run `/api/health`, login, dashboard, accounts, books, scheduled awareness, transactions, account detail, transaction detail, CSV export, reports summary, and disabled-write checks on disposable or copied data before any regular read-only use.
6. If experimenting with writes, use only synthetic/disposable fixtures or restorable copied test books and follow `docs/dogfood/write-alpha-copied-book-runbook.md`, `docs/write-alpha-maintainer-checklist.md`, and `docs/write-alpha-recovery-procedure.md`.
