# v0.2.9-writealpha release value decision

Status: NO_RELEASE.

## Inputs reviewed

- Latest public write-alpha pre-release: `v0.2.8-writealpha`.
- Changes since `v0.2.8-writealpha`: owner dry-run/request/evidence docs, CREATE-one/CREATE-to-PATCH evidence docs, posture/status reconciliation, redaction/test hardening, no new broadly useful runtime write scope.
- Phase 294/295 evidence: accepted narrowly for one copied/restorable working book, one CREATE, and one metadata/memo-only PATCH on the same write-alpha-created transaction.
- Phase 296 posture: DELETE remains blocked/not run; original/private/only-copy writes remain forbidden and unsupported.
- GitHub issues: #36 remains open as the write-readiness tracker.
- CI state at decision time: a newer fix for the Phase 296 public-status test was pushed; exact HEAD CI was still pending/in progress, so publication would be unsafe even if a release were otherwise desirable.

## PM verdict

NO_RELEASE.

## Rationale

A `v0.2.9-writealpha` release would mostly communicate additional evidence and documentation posture, not a user-facing runtime capability or important safety correction for published users. Publishing now risks overstating the narrow Phase 294/295 owner copied-book CREATE-to-PATCH evidence as general write safety.

The existing `v0.2.8-writealpha` pre-release remains the current public experimental write-alpha baseline. The repository can continue documenting evidence and hardening locally without a new tag.

## Explicit non-authorization

- Do not publish `v0.2.9-writealpha` from this decision.
- Do not create a tag, GitHub release, package, image, or stable release.
- Do not claim production readiness, public-internet safety, security audit coverage, broad GnuCash compatibility, DELETE readiness, or safe writes for real/private/original/only-copy books.
- Do not authorize owner DELETE.

## Next step

Phase 298 should create no-release support documentation, not release-candidate artifacts.
