## Summary

`v0.2.7-writealpha` is a conservative pre-alpha write-alpha maintenance pre-release for the Cycle 2 ownership-guard work after `v0.2.6-writealpha`.

The release was published only after Phase 251 called PM, received `AUTHORIZE_RELEASE`, reran the full local release gate, waited for GitHub Actions on the exact release/status commit, and confirmed tag/release absence immediately before publication. Publication created only an annotated git tag and GitHub pre-release; no package, image, production deployment, or write-default change was published.

## What changed since `v0.2.6-writealpha`

- App metadata-only write-alpha transaction ownership markers were added for successful CREATE requests.
- Backend PATCH now requires a same-book app metadata ownership marker before constructing the GnuCash write service. Non-owned historical/imported/manual transactions are rejected with 403 before backup, lock, audit row, or GnuCash mutation.
- Backend DELETE now requires the same same-book ownership marker before constructing the GnuCash write service. Non-owned historical/imported/manual transactions are rejected with 403 before backup, lock, audit row, or GnuCash mutation.
- The transaction detail UI was aligned with the backend ownership boundary: edit/delete controls are hidden for non-owned historical/manual transactions, and write-alpha-owned synthetic transactions can show experimental controls only under explicit write mode.
- Synthetic/disposable Docker/Caddy ownership route-family dogfood passed: one write-alpha-owned synthetic transaction was created, PATCHed, and DELETEd; non-owned PATCH/DELETE probes returned 403 without backup growth; backup/audit/lock/restore/default-reset evidence was recorded as redacted counts/statuses.
- The read-only write-alpha audit summary now exposes safe ownership evidence counters: write-alpha-created marker count, non-owned mutation rejection count, and last successful mutation type, without raw payloads, amounts, memos, account names, or paths.
- Operator docs now state that CREATE creates write-alpha-owned transactions, PATCH/DELETE are limited to those write-alpha-owned transactions for the same app metadata book, and historical/imported/manual GnuCash transactions remain read-only in this app.

## Safety boundaries

- `GNUCASH_WRITES_ENABLED=false` remains the default.
- Write-alpha execution still requires explicit local enablement and `APP_ENV=test`.
- Evidence for this release is synthetic/disposable only. No real/private or only-copy write safety is claimed.
- Ownership guards reduce accidental PATCH/DELETE against historical/manual transactions in this app, but they do not make real/private, original, production, shared, or only-copy books safe for write-alpha.
- No production readiness, stable release status, security audit, hosted SaaS readiness, public-internet safety, direct public-internet deployment recommendation, banking integration, CSV/OFX import, collaborative accounting, or broad GnuCash Desktop/backend compatibility is claimed.
- No package, binary artifact, Docker image, production deployment, real/private book, app DB, backup artifact, `.env`, screenshot/export, token, key, cert, raw private path, account name, memo, amount, or private financial artifact is included.
