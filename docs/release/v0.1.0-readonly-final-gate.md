## Accepted Phase 78 dogfood evidence

Phase 78 evidence is accepted for the v0.1 read-only dogfood gate because the original #25 acceptance criteria allow copied or disposable GnuCash data, and Phase 78 used only a copied/disposable fixture outside git.

Accepted evidence:

- Docker/Caddy deployment used copied/disposable SQL fixture data.
- `GNUCASH_WRITES_ENABLED=false` was verified in runtime config and `/api/health`.
- `/login` returned 200 after the #37 fix.
- Unauthenticated protected route redirected to `/login?next=...`.
- Headless Chromium login reached the dashboard.
- Dashboard, accounts, account detail, transactions, transaction detail, and CSV export route loaded.
- Write UI remained hidden.
- Validate/create/patch write probes returned 403.
- API smoke passed.
- No real financial data, `.env`, app DB, backup, token, screenshot, or raw export was committed.

Remaining limitation: Phase 78 did not use an explicitly provided real personal copied book. This is accepted for `v0.1.0-readonly` because the release notes now make compatibility conservative and require every user to test a copied book first. It is not treated as a publication blocker.
