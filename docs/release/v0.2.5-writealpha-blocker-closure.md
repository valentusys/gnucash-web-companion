# v0.2.5-writealpha Phase 220 blocker-closure note

Date: 2026-05-21
Phase: 227
Status: historical blocker-closure note; superseded by Phase 231 publication

## What was closed

Phase 220 found a no-release blocker in bounded write-alpha DELETE evidence: successful backup-bearing audit rows exceeded the observed backup file count during synthetic/disposable route-family dogfood.

Phases 222–226 closed that blocker narrowly:

- Phase 222 found the concrete evidence bug: second-precision backup filenames for rapid same-named synthetic route-family copies could collide, and overwrite-capable copy behavior could collapse multiple backup-bearing audit rows into fewer backup artifacts.
- Phase 223 added deterministic backup identity/evidence coverage and redacted operator refs.
- Phase 224 reran bounded synthetic/disposable DELETE restore proof successfully.
- Phase 225 reran the create/PATCH/DELETE backup-audit matrix successfully with one matching backup and one successful audit row for each successful isolated route-family write.
- Phase 226 reran the default-read-only Docker/Caddy product path successfully with `GNUCASH_WRITES_ENABLED=false`.

Phases 227–229 kept that closure in release-support/public-status artifacts without changing release state at that time: Phase 227 documented the narrow operator-facing closure, Phase 228 passed current-HEAD fresh-clone and `v0.2.4-writealpha` upgrade smokes with writes disabled, and Phase 229 refreshed the public status/release-doc drift guard.

Phase 231 later superseded the no-release state by publishing `v0.2.5-writealpha` as a conservative GitHub pre-release after Phase 230 dogfood evidence, local gates, public status guard, sensitive-file hygiene, and exact release/status commit CI passed.

## What this does not mean

This note itself did not publish `v0.2.5-writealpha`, change the public release, or approve production write mode. It is retained as historical release-support context for the Phase 220 blocker closure.

Current public status after Phase 231/232 is:

- current read-only pre-release: `v0.1.7-readonly`;
- current write-alpha pre-release: `v0.2.5-writealpha`;
- the Phase 221 no-release verdict is historical and superseded by the Phase 231 `v0.2.5-writealpha` publication;
- `GNUCASH_WRITES_ENABLED=false` remains the default;
- write-alpha remains experimental and constrained to explicit `APP_ENV=test` disposable/copy-book testing;
- no real/private-book or only-copy write safety is claimed;
- the project remains pre-alpha, not production-ready, and not security-audited.

## Operator/release wording rule

When referencing the closure in release-support artifacts, use wording like:

> The Phase 220 no-release blocker was closed as synthetic/disposable backup-audit evidence remediation: matching redacted audit rows and readable backup artifacts were re-established after the backup identity fix. This does not change write-alpha safety boundaries.

Avoid wording that implies broad backup reliability, production readiness, public-internet safety, security audit coverage, or safe writes against real/private or only-copy books.
