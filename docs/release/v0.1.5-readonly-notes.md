# v0.1.5-readonly Release Notes

> Prepared in Phase 151 as an unpublished maintenance pre-release candidate.
>
> Publication status: not published. No tag, GitHub release, package, binary artifact, Docker image, or production deployment was created in Phase 151.

## Status

`v0.1.5-readonly` is a conservative pre-alpha read-only maintenance candidate after the published `v0.1.4-readonly` read-only pre-release and the separately published `v0.2.0-writealpha` experimental pre-release.

The project remains read-only by default. GnuCash Desktop remains the authoritative editor. This project is not production-ready, not security-audited, and not a hosted financial service. Test with disposable fixtures or copied GnuCash SQL books first, keep backups, and do not expose early deployments directly to the public internet.

Controlled-write code may exist in the repository as experimental post-MVP/write-alpha work, but it is outside this read-only maintenance candidate and remains disabled by default:

```text
GNUCASH_WRITES_ENABLED=false
```

## What changed since v0.1.4-readonly

This candidate summarizes read-only UX, localization, synthetic dogfood, and release-readiness work completed after `v0.1.4-readonly`:

- Phase 143: made the active accessible book and read-only/default-write-disabled posture visible in the authenticated app shell.
- Phase 144: added a local accessible account-tree filter for large read-only account trees, with filtered counts and no browser-storage/API/write behavior.
- Phase 145: improved transaction list/export confidence with a current-view summary, page range, newest-first ordering, filter parity, and the 10,000-row CSV export cap reminder.
- Phase 146: polished transaction detail/split readability with responsive metadata, mobile split cards, memo/account-id visibility, reconciliation-state display, and safe empty-split handling.
- Phase 147: clarified dashboard/reporting limitations for `reporting_basis=base_currency_only`, no currency conversion, excluded mixed currencies, and `XXX`/zero-total edge cases.
- Phase 148: improved `/books` self-hosting readiness with app-metadata-only operator guidance, current/default/read-only/access/storage/status clarity, unsupported MVP management-action copy, and no private path rendering.
- Phase 149: expanded Russian localization coverage for new read-only UX from Phases 143–148 through the existing catalog while keeping English canonical and localization partial/opt-in.
- Phase 150: reran synthetic/disposable Docker/Caddy read-only API and headless browser dogfood with `GNUCASH_WRITES_ENABLED=false`; read-only routes, CSV export, hidden write UI, disabled validate/create/patch probes, and no-artifact checks passed.
- Phase 151: prepared these release notes, release-prep checklist, final gate, status updates, and handoff without publishing.

## Read-only maintenance value

The candidate is meaningful because it improves the read-only operator/user experience and refreshes disposable runtime evidence without expanding write scope:

- clearer always-visible current-book/read-only status;
- better account-tree discovery for large books;
- clearer transaction filter/export state and CSV cap messaging;
- more readable transaction details and split metadata on mobile/desktop;
- more honest dashboard/reporting limitations for mixed-currency and unknown-base-currency books;
- safer `/books` operator guidance with no management writes exposed;
- Russian localization coverage for the latest read-only UX slice;
- fresh synthetic Docker/browser dogfood evidence after those changes.

## Known limitations and non-claims

This candidate does not claim:

- production readiness;
- security audit completion;
- safe direct public-internet exposure;
- broad compatibility with every GnuCash Desktop version or every backend;
- PostgreSQL, MySQL, MariaDB, XML-book, or arbitrary real-world-book compatibility;
- hosted SaaS readiness;
- collaborative accounting, family-wallet positioning, or real-time multi-user editing;
- account, transaction, invoice, bill, customer, vendor, scheduled-transaction editing, CSV/OFX import, or banking integrations;
- safe production write mode for real books;
- production scalability or full real-world-book coverage from synthetic dogfood evidence.

Compatibility and dogfood evidence remain intentionally narrow: committed synthetic/disposable SQLite fixtures, copied/disposable metadata procedures, safe local tooling probes, previous redacted copied-book dogfood evidence from earlier releases, and Phase 150 synthetic Docker/Caddy dogfood. Users must test their own copied book before relying on the app for regular read-only browsing.

## Upgrade notes from v0.1.4-readonly

1. Back up app metadata and any copied test books used with the app.
2. Review `.env.example` and keep `GNUCASH_WRITES_ENABLED=false`.
3. After a later authorized publication phase, check out the `v0.1.5-readonly` tag from the GitHub pre-release. Until then, this is only an unpublished candidate document.
4. Rebuild/restart Docker Compose.
5. Run `/api/health`, login, dashboard, accounts, books, scheduled awareness, transactions, account detail, transaction detail, CSV export, and disabled-write checks on disposable or copied data before regular use.
6. Keep `.env`, app DBs, GnuCash books, backups, real financial exports/screenshots, secrets, tokens, keys, and certs out of git.
