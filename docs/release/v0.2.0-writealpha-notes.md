# v0.2.0-writealpha Release Notes

> Status: published as a GitHub pre-release after explicit Val authorization.
>
> Publication status: published / pre-release.
>
> The release tag and GitHub pre-release are publication artifacts only; they do not enable write mode by default.

## Status

`v0.2.0-writealpha` is a published pre-alpha write-alpha pre-release after the published `v0.1.3-readonly` read-only pre-release.

This published pre-release remains pre-alpha, experimental, not production-ready, and not security-audited. Do not expose early deployments directly to the public internet. Do not use the write-alpha paths against a real/private or only copy of a GnuCash book.

The application remains read-only by default:

```text
GNUCASH_WRITES_ENABLED=false
```

Even when write mode is explicitly enabled by an operator, the backend write-alpha routes still require the test-environment gate:

```text
APP_ENV=test
```

The write-alpha evidence for this published pre-release is synthetic/disposable fixture evidence only. It is not a claim that real-book writes are safe.

## What changed since v0.1.3-readonly

The published pre-release summarizes Phases 126–132 after `v0.1.3-readonly`:

- Phase 126 — read-only transaction filter polish and GitHub #11/#12 triage: transaction query matching includes transaction notes when exposed by piecash, UI/docs clarify description/notes/split-memo search semantics, saved presets remain de-scoped to preserve URL-only behavior, and scheduled/recurring awareness was closed as covered by the conservative read-only implementation.
- Phase 127 — GnuCash Desktop compatibility evidence refresh: local `gnucash` and `gnucash-cli` tooling remain unavailable, so compatibility docs record a blocker/manual procedure instead of fabricated Desktop-generated fixture evidence.
- Phase 128 — write-alpha create-route concurrency and error-path expansion: copied/disposable fixture tests cover two parallel creates, lock contention, post-backup failure, lock release, failed audit, intact backup evidence, no book mutation, and read-only/viewer rejection before write-service construction.
- Phase 129 — write-alpha recovery and maintainer-review documentation: recovery and maintainer checklist docs now cover containment, backup selection, stale-lock cleanup, restore, integrity checks, damaged-book triage, default-disabled config, `APP_ENV=test` gating, fixture scope, and hygiene.
- Phase 130 — write-alpha PATCH transaction hardening: experimental PATCH remains disabled by default and test-gated when enabled; route/service tests cover successful patch, 404 missing transaction before mutation, validation failure, failed audit with backup path, no backup leak, lock release, intact backup, and concurrent PATCH+CREATE lock contention.
- Phase 131 — explicitly authorized write-alpha DELETE transaction hardening: experimental DELETE remains disabled by default and test-gated when enabled; tests cover successful deletion, missing transaction before mutation, synthetic post-backup failure, audit/backup/lock lifecycle, read-only/viewer rejection before write service, concurrent DELETE+CREATE lock contention, and a hidden-by-default frontend delete form requiring acknowledgement and browser confirmation.
- Phase 132 — release gate artifacts for this write-alpha pre-release; Phase 132 itself did not publish, and the tag/GitHub pre-release were created later only after explicit Val authorization.

## Write-alpha scope

The published pre-release write-alpha CRUD surface is narrow:

- create transaction;
- PATCH transaction metadata/split memo scope as implemented by the write service;
- DELETE transaction, explicitly authorized for Phase 131 only.

All write-alpha routes must remain disabled unless both gates are satisfied:

```text
GNUCASH_WRITES_ENABLED=true
APP_ENV=test
```

The default documented and configured posture remains:

```text
GNUCASH_WRITES_ENABLED=false
```

## Safety boundaries and non-claims

This published pre-release does not claim:

- production readiness;
- security audit completion;
- safe direct public-internet exposure;
- safe write mode for real/private GnuCash books;
- broad compatibility with every GnuCash Desktop version or every backend;
- PostgreSQL, MySQL, MariaDB, XML-book, or arbitrary real-world-book compatibility;
- hosted SaaS readiness;
- collaborative accounting, family-wallet positioning, or real-time multi-user editing;
- invoice, bill, customer, vendor, scheduled-transaction editing;
- account editing, recurring transaction editing, CSV/OFX import, or banking integrations;
- safe use on the only copy of a GnuCash book.

Use only synthetic/disposable fixtures or copied books you can restore or delete. Keep backups. Keep `.env`, app DBs, GnuCash books, backups, real financial exports/screenshots, secrets, tokens, keys, and certs out of git.

## Upgrade notes from v0.1.3-readonly

1. Use the published `v0.2.0-writealpha` GitHub pre-release only as a pre-alpha / experimental test-copy milestone.
2. Back up app metadata and any copied test books used with the app.
3. Review `.env.example` and keep `GNUCASH_WRITES_ENABLED=false` unless intentionally running synthetic/disposable write-alpha tests.
4. Never enable write-alpha routes outside a disposable/test environment; write execution still requires `APP_ENV=test`.
5. Rebuild/restart Docker Compose.
6. Run `/api/health`, login, dashboard, accounts, books, scheduled awareness, transactions, account detail, transaction detail, CSV export, and disabled-write checks on disposable or copied data before any regular read-only use.
7. If experimenting with writes, use only synthetic/disposable fixtures and follow `docs/write-alpha-maintainer-checklist.md` plus `docs/write-alpha-recovery-procedure.md`.
