# v0.0.2-prealpha Release Candidate Notes

> **Status: pre-alpha release** — not a production release. For review and experimentation only.

## Overview

`v0.0.2-prealpha` is the second pre-alpha release for `gnucash-web-companion`. It follows `v0.0.1-prealpha` and incorporates Phases 17–42, focusing on integration testing, safety hardening, multi-book UI foundations, CSV export, release documentation consistency, discoverability readiness, a conservative compatibility baseline, read-only transaction filter polish, clearer read-only status in the app shell, disabled-write regression coverage, controlled-writes documentation cleanup, public status baseline synchronization, personal dogfood readiness, automated read-only smoke testing, explicit write-mode UI warning/acknowledgement coverage, release-gate audit, and final pre-alpha publication.

The `v0.0.2-prealpha` tag and GitHub pre-release were published in Phase 42 after the Phase 41 release-gate audit passed, accepted blockers were fixed, post-push CI was green, and local release checks passed.

## What's new since v0.0.1-prealpha

### Integration testing and safety

- **Phase 17** — Synthetic GnuCash SQLite fixture created using piecash. 19 read-only integration tests validate the full read-only path against a real disposable book.
- **Phase 19** — 11 multi-currency integration tests confirm that mixed-currency books are handled safely (non-base-currency values excluded from reports). Auth cookie security documentation added.
- **Phase 22** — 30 controlled write integration tests against real disposable piecash books. Covers create, patch, backup, audit, lock lifecycle, contention, rejection scenarios, and read-back verification.
- **Phase 23** — 6 backup restore smoke tests. Confirms backups created before write operations can be restored, preserving original book state.
- **Phase 32** — Disabled-write regression tests prove validate/create/patch routes return read-only 403 responses with `GNUCASH_WRITES_ENABLED=false` before `_write_service_for` / `GnuCashWriteService` is constructed.

### Write lock hardening

- **Phase 21** — In-process `threading.Lock` replaced with `fcntl.flock()`-based file locking. Lock files are stored under `/data/locks/` with sanitized book IDs. Safe for multi-worker deployments (e.g. uvicorn with `--workers > 1`).

### Multi-book UI foundation

- **Phase 20** — Book switcher component added to frontend navigation. All page-level data loads migrated to explicit book-aware routes (`/books/{book_id}/...`). Single-book installations show plain text; multi-book installations show a dropdown. Backend multi-book access filtering tested with 8 new tests.

### CSV export

- **Phase 24** — Read-only CSV export endpoint (`GET /books/{book_id}/transactions/export`). Preserves current filters (query, date_from, date_to, account_id). 10,000 row cap. Frontend «Экспорт CSV» button on transactions page. 8 backend tests cover auth, headers, data, filters, access denial, and Content-Disposition.
- **Phase 30** — Frontend amount range filters (`min_amount`, `max_amount`) added to the transactions page and preserved in CSV export URLs. Export button now shows active filter count. Backend rejects inverted amount ranges before querying GnuCash.

### Documentation, audit, and release readiness

- **Phase 18** — 7 screenshots added to README (login, dashboard desktop/mobile, accounts tree, transactions list, transaction detail, dark mode). All use synthetic fixture data.
- **Phase 25** — README, CHANGELOG, controlled-write notes, release candidate notes, and backlog synchronized after Phases 17–24.
- **Phase 26** — Independent audit findings resolved by syncing stale status/release docs and GitHub automation notes.
- **Phase 27** — Discoverability and community announcement readiness docs added, including conservative announcement copy and social preview guidance.
- **Phase 28** — GnuCash compatibility matrix documented and tested for committed synthetic SQLite fixtures.
- **Phase 29** — Audit refreshed and release/status docs synchronized through Phase 29 without publishing a tag or release.
- **Phase 31** — Authenticated app shell now shows a global read-only-by-default safety banner reminding users that GnuCash Desktop remains the authoritative editor and web writes require an explicit post-MVP feature flag.
- **Phase 33** — Controlled-writes documentation cleaned up and public status synchronized after disabled-write bypass regression coverage, while keeping write mode experimental and disabled by default.
- **Phase 34** — Public README/status baseline synchronized after the Phase 33 audit finding, without publishing a tag or release.
- **Phase 35** — Public status synchronized through Phase 34/35 and the stale controlled-writes limitation about frontend amount filters was removed.
- **Phase 36** — Experimental write mode now displays explicit warnings near the write entry point and on `/transactions/new`, and final create requires acknowledgement that writes are post-MVP, disabled by default, for disposable/test copies only, and subordinate to GnuCash Desktop.
- **Phase 37** — Independent audit and baseline sync confirmed the post-Phase-36 read-only/default-write safety posture and synchronized public status docs.
- **Phase 38** — Personal read-only dogfood guide and manual smoke checklist prepared safe copied-book testing instructions.
- **Phase 39** — Automated read-only API smoke script added for local Docker deployments, including disabled-write 403 probes.
- **Phase 40** — Release-candidate checklist created and notes/README/CHANGELOG synchronized for `v0.0.2-prealpha` without publishing a tag or GitHub release.
- **Phase 41** — Release-gate audit completed for `v0.0.2-prealpha`; documentation/link hygiene blockers were fixed, write-gating was re-verified, and publication remains reserved for the explicit Phase 42 release step.
- **Phase 42** — `v0.0.2-prealpha` published as a Git tag and GitHub pre-release after the Phase 41 gate and green checks.

## Safety status

- MVP v0.1 remains **read-only by default**.
- `GNUCASH_WRITES_ENABLED=false` by default.
- Controlled-write code is experimental, post-MVP, and disabled by default.
- Disabled-write bypass regression coverage exists for validate/create/patch routes; this is safety coverage only and does not make write mode production-ready.
- Authenticated UI shows a persistent read-only-by-default reminder.
- Experimental write UI, when explicitly enabled, now requires explicit warning acknowledgement before final create submission.
- piecash write compatibility is **not guaranteed** for all GnuCash versions.
- No production write-mode guarantee.
- Use only with disposable test copies of GnuCash books.
- Personal dogfood and smoke-check documentation exists for copied-book testing; it is not a production deployment certification.

## Known limitations

- piecash compatibility must be validated against supported GnuCash versions.
- CSV export now preserves frontend amount range filters; export customization remains intentionally basic.
- Local read-only API smoke automation exists, but live smoke execution requires a running local deployment and copied/disposable book setup.
- Multi-book UI is structural; full multi-user access control is post-MVP.
- Concurrency tests for write operations are still pending.
- No production-readiness or security audit guarantee.

## Compatibility

- GnuCash SQL SQLite fixture compatibility is documented in `docs/gnucash-compatibility.md`.
- The committed synthetic fixtures have schema markers `Gnucash = 3000000` and `Gnucash-Resave = 19920`.
- PostgreSQL/MySQL/MariaDB backends, XML books, and books generated by multiple GnuCash Desktop versions are not yet validated.
- Docker Compose deployment with Caddy reverse proxy.

## Verification

Backend:
```bash
cd apps/api && pytest -q
```

Frontend:
```bash
cd apps/web && npm run check && npm run test:auth-routes && npm run build
```

Docker config:
```bash
JWT_SECRET=dummy-validation-secret APP_ADMIN_PASSWORD=dummy docker compose config --quiet
```

Release-gate checklist:
```bash
git diff --check
```

Optional local deployment smoke with copied/disposable book only:
```bash
SMOKE_API_BASE_URL=http://localhost:8080/api \
SMOKE_ADMIN_USERNAME=admin \
SMOKE_ADMIN_PASSWORD='<local-admin-password>' \
python3 scripts/smoke/read-only-api-smoke.py
```
