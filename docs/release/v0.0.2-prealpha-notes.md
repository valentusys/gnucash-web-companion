# v0.0.2-prealpha Release Candidate Notes

> **Status: pre-alpha / release candidate** — not a production release. For review and experimentation only.

## Overview

`v0.0.2-prealpha` is the second pre-alpha release candidate for `gnucash-web-companion`. It follows `v0.0.1-prealpha` and incorporates Phases 17–30, focusing on integration testing, safety hardening, multi-book UI foundations, CSV export, release documentation consistency, discoverability readiness, a conservative compatibility baseline, and read-only transaction filter polish.

No git tag or GitHub release is created for this candidate. These notes are for maintainer review and roadmap tracking.

## What's new since v0.0.1-prealpha

### Integration testing and safety

- **Phase 17** — Synthetic GnuCash SQLite fixture created using piecash. 19 read-only integration tests validate the full read-only path against a real disposable book.
- **Phase 19** — 11 multi-currency integration tests confirm that mixed-currency books are handled safely (non-base-currency values excluded from reports). Auth cookie security documentation added.
- **Phase 22** — 30 controlled write integration tests against real disposable piecash books. Covers create, patch, backup, audit, lock lifecycle, contention, rejection scenarios, and read-back verification.
- **Phase 23** — 6 backup restore smoke tests. Confirms backups created before write operations can be restored, preserving original book state.

### Write lock hardening

- **Phase 21** — In-process `threading.Lock` replaced with `fcntl.flock()`-based file locking. Lock files are stored under `/data/locks/` with sanitized book IDs. Safe for multi-worker deployments (e.g. uvicorn with `--workers > 1`).

### Multi-book UI foundation

- **Phase 20** — Book switcher component added to frontend navigation. All page-level data loads migrated to explicit book-aware routes (`/books/{book_id}/...`). Single-book installations show plain text; multi-book installations show a dropdown. Backend multi-book access filtering tested with 8 new tests.

### CSV export

- **Phase 24** — Read-only CSV export endpoint (`GET /books/{book_id}/transactions/export`). Preserves current filters (query, date_from, date_to, account_id). 10,000 row cap. Frontend «Экспорт CSV» button on transactions page. 8 backend tests cover auth, headers, data, filters, access denial, and Content-Disposition.
- **Phase 30** — Frontend amount range filters (`min_amount`, `max_amount`) added to the transactions page and preserved in CSV export URLs. Export button now shows active filter count. Backend rejects inverted amount ranges before querying GnuCash.

### Documentation, audit, and release readiness

- **Phase 18** — 7 screenshots added to README (login, dashboard desktop/mobile, accounts tree, transactions list, transaction detail, dark mode). All use synthetic fixture data.
- **Phase 25** — README, CHANGELOG, controlled-write notes, release candidate notes, and backlog synchronized after Phases 17–24.
- **Phase 26** — Independent audit findings resolved by syncing stale status/release docs and GitHub automation notes.
- **Phase 27** — Discoverability and community announcement readiness docs added, including conservative announcement copy and social preview guidance.
- **Phase 28** — GnuCash compatibility matrix documented and tested for committed synthetic SQLite fixtures.
- **Phase 29** — Audit refreshed and release/status docs synchronized through Phase 29 without publishing a tag or release.

## Safety status

- MVP v0.1 remains **read-only by default**.
- `GNUCASH_WRITES_ENABLED=false` by default.
- Controlled-write code is experimental, post-MVP, and disabled by default.
- piecash write compatibility is **not guaranteed** for all GnuCash versions.
- No production write-mode guarantee.
- Use only with disposable test copies of GnuCash books.

## Known limitations

- piecash compatibility must be validated against supported GnuCash versions.
- CSV export now preserves frontend amount range filters; export customization remains intentionally basic.
- Multi-book UI is structural; full multi-user access control is post-MVP.
- Concurrency tests for write operations are still pending.
- UI warning before write submission is not yet implemented.
- No production-readiness or security audit guarantee.

## Compatibility

- GnuCash SQL SQLite fixture compatibility is documented in `docs/gnucash-compatibility.md`.
- The committed synthetic fixtures have schema markers `Gnucash = 3000000` and `Gnucash-Resave = 19920`.
- PostgreSQL/MySQL/MariaDB backends, XML books, and books generated by multiple GnuCash Desktop versions are not yet validated.
- Docker Compose deployment with Caddy reverse proxy.

## Verification

Backend:
```bash
cd apps/api && pytest -q
```

Frontend:
```bash
cd apps/web && npm run check && npm run test:auth-routes && npm run build
```

Docker config:
```bash
JWT_SECRET=dummy-validation-secret APP_ADMIN_PASSWORD=dummy docker compose config --quiet
```
