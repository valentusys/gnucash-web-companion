# v0.4 owner-writebeta readiness remains unreleased

Status: `UNRELEASED_UNTIL_OWNER_APPROVAL`.

This document explains the release boundary for #36 without preparing a release,
tag, package, image, or public write-beta claim. The companion boundary doc is
[owner-writebeta owner-approval boundary](owner-writebeta-owner-approval-boundary.md).

## Reader summary

Owner-writebeta readiness work is maintenance evidence only. It records that some
controlled-write checks and one narrow copied-book dogfood path have been reviewed.
It does not mean owner-writebeta is available for general use, public beta use, or
real/private/original/working/only-copy book mutation.

The current public release remains `v0.5.0-public-readonly-beta`. The
`v0.4.0-owner-writebeta` line is not published and must stay unreleased unless the
owner explicitly approves a later release-candidate package.

## Why no release is published

The blocker is not just test status. It is an ownership and public-signal decision:
clean local checks can support repository hygiene, but they cannot convert bounded
maintenance evidence into release authorization.

Read this document as a no-release explanation, not as a release checklist. Its
purpose is to keep reviewer expectations aligned while #36 remains open and the
owner has not approved release-candidate preparation.

1. #36 is still open. The owner has not approved closure of all remaining
   controlled-write readiness gates.
2. The accepted W3 evidence is deliberately narrow: one staged outside-git
   copied/restorable target, exact operation counts, and redacted evidence only.
3. Supported-version write compatibility is not accepted as a release claim.
4. Real/private/original/working/only-copy book mutation is outside the approved
   evidence scope and remains unauthorized.
5. A release artifact would be easy to misread as public write beta availability or
   broader write safety. The repository must avoid that signal until owner approval.

## What can be said now

- Repository health and documentation checks may pass.
- Controlled-write code remains disabled by default.
- `GNUCASH_WRITES_ENABLED=false` remains the default posture.
- Enabled write-alpha/writebeta paths remain `APP_ENV=test` gated.
- The W3 copied-book result is accepted only for the exact copied/restorable scope.
- No tag, GitHub release, package, image, or release notes are authorized here.

## What cannot be said now

- No public write beta claim.
- No stable, production-ready, or security-audited claim.
- No broad GnuCash version compatibility claim.
- No real/private/original/working/only-copy book safety claim.
- No implication that passing local checks authorizes release publication.

## Reconsideration boundary

A later worker may prepare release-candidate artifacts only after an explicit owner
or PM decision changes the state from `NO_RELEASE_KEEP_MAINTENANCE` to a named
release-candidate preparation task.

Until then, release docs should stay conservative: explain blockers, preserve write
defaults, and record that owner-writebeta readiness remains unreleased.
