# v0.1.4-readonly Release Notes

> Published in Phase 142 as an authorized `v0.1.4-readonly` maintenance pre-release.
>
> Publication status: GitHub pre-release. No package, binary artifact, Docker image, or production deployment is published.

## Status

`v0.1.4-readonly` is a conservative pre-alpha read-only maintenance pre-release after the published `v0.1.3-readonly` read-only pre-release and the separately published `v0.2.0-writealpha` experimental pre-release.

The project remains read-only by default. GnuCash Desktop remains the authoritative editor. This project is not production-ready, not security-audited, and not a hosted financial service. Test with disposable fixtures or copied GnuCash SQL books first, keep backups, and do not expose early deployments directly to the public internet.

Controlled-write code may exist in the repository as experimental post-MVP/write-alpha work, but it is outside this read-only maintenance candidate and remains disabled by default:

```text
GNUCASH_WRITES_ENABLED=false
```

- Phase 135: polished mobile navigation and narrow-screen transaction-detail split layout with touch-friendly controls and clearer mobile/desktop breakpoints.
- Phase 136: refreshed GnuCash compatibility documentation while keeping evidence boundaries explicit: current automated coverage remains synthetic/disposable fixture evidence only and no broad Desktop-version compatibility is claimed.
- Phase 137: refreshed local/LAN/VPN deployment hardening documentation, JWT-secret guidance, exact CORS-origin recommendations, app metadata DB backup expectations, and pre-deployment checks.
- Phase 138: synchronized public README, Russian README, changelog, roadmap, and status documentation after the recent read-only maintenance phases.
- Phase 139: reran synthetic/disposable Docker/Caddy dogfood with `GNUCASH_WRITES_ENABLED=false`; read-only API/browser paths and disabled write probes passed using only committed synthetic fixture data copied into ignored runtime paths.
- Phase 140: audited readiness for this maintenance candidate and found a documentation-drift blocker.
- Phase 141: prepared the `v0.1.4-readonly` release notes, checklist, final gate, changelog/status updates, and handoff without publishing.
- Phase 142: re-ran the publication gate and published `v0.1.4-readonly` as an authorized GitHub pre-release.

## Read-only maintenance value

The candidate is meaningful because it improves the read-only user experience and self-hosting evidence without expanding write scope:

- clearer empty/error states for common read-only edge cases;
- more stable perceived loading behavior on core read-only pages;
- better small-screen navigation and transaction detail readability;
- refreshed compatibility and deployment documentation with conservative limits;
- fresh synthetic/disposable Docker/Caddy dogfood evidence for core read-only paths;
- a checkable release gate and publication evidence for the authorized pre-release.

## Known limitations and non-claims

This candidate does not claim:

- production readiness;
- security audit completion;
- safe direct public-internet exposure;
- broad compatibility with every GnuCash Desktop version or every backend;
- PostgreSQL, MySQL, MariaDB, XML-book, or arbitrary real-world-book compatibility;
- hosted SaaS readiness;
- collaborative accounting, family-wallet positioning, or real-time multi-user editing;
- account, transaction, invoice, bill, customer, vendor, scheduled-transaction editing, CSV/OFX import, or banking integrations;
- safe production write mode for real books;
- production scalability or full real-world-book coverage from synthetic dogfood evidence.

Compatibility and dogfood evidence remain intentionally narrow: committed synthetic/disposable SQLite fixtures, copied/disposable metadata procedures, safe local tooling probes, previous redacted copied-book dogfood evidence from earlier releases, and Phase 139 synthetic Docker/Caddy dogfood. Users must test their own copied book before relying on the app for regular read-only browsing.

## Upgrade notes from v0.1.3-readonly

1. Back up app metadata and any copied test books used with the app.
2. Review `.env.example` and keep `GNUCASH_WRITES_ENABLED=false`.
3. Check out the `v0.1.4-readonly` tag from the GitHub pre-release.
4. Rebuild/restart Docker Compose.
5. Run `/api/health`, login, dashboard, accounts, books, scheduled awareness, transactions, account detail, transaction detail, CSV export, and disabled-write checks on disposable or copied data before regular use.
6. Keep `.env`, app DBs, GnuCash books, backups, real financial exports/screenshots, secrets, tokens, keys, and certs out of git.
