# Phase 64 Audit — GnuCash Compatibility Claims

Date: 2026-05-18

## Executive summary

Phase 64 audited the repository's GnuCash compatibility claims against the auditor roadmap. The current public docs are conservative: they describe tested coverage as GnuCash SQL SQLite fixture paths, explicitly separate XML from SQL books, mark PostgreSQL/MySQL/MariaDB as not formally tested, and avoid any claim that the app supports all GnuCash books or all GnuCash Desktop versions.

No Phase 64 compatibility blocker was found. The important limitation remains that compatibility coverage is narrow: current automated evidence covers committed/generated synthetic SQLite fixtures through `piecash`, not a real multi-version GnuCash Desktop compatibility matrix. GitHub #22 correctly remains open for future real-version fixture coverage.

This audit does not unblock `v0.1.0-readonly` publication. Existing release blockers #24 and #25 remain open.

## Verdict

No compatibility-claims blocker found for the current pre-alpha/read-only posture.

The project must stay conservative: v0.1 docs and any future release notes may claim only tested GnuCash SQL SQLite fixture coverage, not broad GnuCash Desktop, XML, PostgreSQL, MySQL, or MariaDB compatibility.

## Top blockers

None found in the Phase 64 compatibility-claims scope.

Carried forward blockers before any `v0.1.0-readonly` publication:

1. #24 — conservative `v0.1.0-readonly` release notes are still required before publication.
2. #25 — copied/disposable-data runtime smoke/dogfood evidence is still required before publication.

## Important non-blockers

1. GitHub #22 remains open for real GnuCash Desktop version fixture coverage. This is important compatibility hardening, but current v0.1 planning already allows it to remain open if release notes clearly limit compatibility to validated SQLite fixture paths and tell users to test copied books first.
2. Existing compatibility tests validate synthetic SQLite fixture paths only; this is honest but narrow.
3. XML books are out of scope for the current SQL-book MVP and are documented as such.
4. PostgreSQL/MySQL/MariaDB backends are not formally tested and must remain unclaimed/experimental until explicit fixtures and tests exist.

## Product consistency

The audited docs keep the correct product model:

- MVP remains read-only by default.
- GnuCash Desktop remains the authoritative editor.
- The project is a self-hosted companion, not a GnuCash replacement.
- The project is not positioned as SaaS or collaborative accounting.
- Multi-book language remains about independent books, not collaborative editing.

## Compatibility claims

Current compatibility evidence is limited and honestly presented:

- `docs/gnucash-compatibility.md` lists two committed synthetic SQLite fixtures and one generated synthetic SQLite fixture path.
- `docs/gnucash-compatibility-fixture-v1.md` states the generated fixture is `piecash`-generated, synthetic, disposable, and not broad GnuCash Desktop compatibility coverage.
- `docs/gnucash-version-fixture-plan.md` defines how future real-version fixtures should be created and what metadata must be recorded.
- `docs/release/v0.1.0-readonly-plan.md` explicitly excludes broad GnuCash version compatibility guarantees, PostgreSQL/MySQL/MariaDB/XML guarantees, and arbitrary real-world book feature guarantees.
- `docs/release/v0.1.0-readonly-checklist.md` includes explicit compatibility release gates.

No wording was found that claims support for all GnuCash books, all GnuCash Desktop versions, XML books, or PostgreSQL/MySQL/MariaDB backends.

## Safety boundary

Phase 64 did not require product-code changes. The repository still documents and configures the default safety boundary:

- `.env.example` contains `GNUCASH_WRITES_ENABLED=false`.
- `apps/api/app/config.py` defaults `Settings.gnucash_writes_enabled` to `False`.
- Controlled writes remain experimental/post-MVP and disabled by default.
- No write-scope expansion is accepted by this audit.

## Release/readme/docs consistency

README, release planning docs, and compatibility docs are aligned on compatibility limitations. No `v0.1.0-readonly` release exists yet, which remains consistent with the unresolved release blockers #24 and #25.

For any future release notes, the required compatibility wording must stay narrow:

- Tested: GnuCash SQL SQLite fixture paths used by the automated suite.
- Not claimed: all GnuCash Desktop versions, PostgreSQL/MySQL/MariaDB, XML books, arbitrary real-world book features, production environments.
- User guidance: test copied/disposable books first and keep backups.

## GitHub project hygiene

## Security notes

No new security risk was introduced by the audit. The compatibility docs avoid asking users to publish real financial data and include reminders to avoid real account names, descriptions, balances, transaction data, private paths, screenshots, CSV exports, `.env`, app DBs, backups, secrets, keys, or tokens.
