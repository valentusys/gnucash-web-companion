# v0.4 compatibility blocker decision

Status: #22 remains open. The Desktop-generated synthetic SQLite fixture gap is a release-risk
blocker for broad compatibility, real-book, public-write, stable, production, and security-audited
claims. For an owner-only copied-book scoped pre-release it could be classified as a known limitation
only if PM explicitly accepts the risk in the final release gate. PM did not accept that risk in this
package, so the decision remains `NO_RELEASE_KEEP_MAINTENANCE`.

## Scope reviewed

- GitHub issue #22 body/comments through the after-W3 restart package.
- `docs/gnucash-compatibility.md`.
- `docs/gnucash-desktop-fixture-capture.md`.

## Exact current blocker

No isolated Desktop-generated synthetic SQLite fixture has been created and validated. The next safe
step remains:

1. use an isolated disposable GUI/manual-safe Desktop environment;
2. create/save a synthetic SQLite book there;
3. run the fail-closed candidate preflight;
4. run default-read-only validation with `GNUCASH_WRITES_ENABLED=false`;
5. publish only redacted metadata and no private book/app DB/backups/exports/screenshots/raw rows.

## Safety summary

This decision packet is non-mutating. It requests no private books and makes no compatibility claim
beyond existing synthetic/disposable and narrowly copied/restorable evidence.
