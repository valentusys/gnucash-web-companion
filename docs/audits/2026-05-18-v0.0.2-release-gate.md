# Independent Audit — 2026-05-18 v0.0.2 Release Gate

## Executive summary

`main` is substantially ahead of `v0.0.1-prealpha`, and the `v0.0.2-prealpha` candidate is documented as a conservative pre-alpha, not a production release. The read-only-by-default boundary is still intact: `Settings.gnucash_writes_enabled` defaults to `False`, the write routes call `_ensure_writes_enabled()` before resolving books/access or constructing `GnuCashWriteService`, and committed regression tests cover disabled validate/create/patch routes.

The gate found small release/documentation hygiene blockers that must be fixed before publishing: README must point to this release-gate audit, the candidate notes contain stale/broken repo-relative links in the related-docs section, and GitHub issue #18 should be closed or explicitly triaged because its technical acceptance criteria are already satisfied by Phase 32 and re-checked in this gate.

## Verdict

Ready after listed blockers.

No tag or GitHub release should be published until the engineer fixes the blockers below, required checks pass, and Phase 42 explicitly performs the release.

## Top blockers

1. README still lists the Phase 37 audit as the latest audit. For the `v0.0.2-prealpha` gate it must point to this Phase 41 release-gate audit.
2. `docs/release/v0.0.2-prealpha-notes.md` has broken/stale relative links in the related-documents section (`docs/v0.2-controlled-writes.md`, `docs/release/...`, `CHANGELOG.md` from inside `docs/release/`). Fix before using the file as release notes.
3. GitHub issue #18 remains open even though the disabled-write bypass acceptance criteria are satisfied by committed tests and were re-checked during the release gate. Close it or add explicit release-triage stating it is no longer a blocker.

## Important non-blockers

1. `v0.0.2-prealpha` tag/release does not exist yet. This is correct for Phase 41; publication belongs to Phase 42 only.
2. Optional live local smoke was not run because it requires a running deployment and local admin/book setup. This is documented as deployment-time smoke and is not a release-gate blocker for a pre-alpha.
3. Open issues #11, #12, #13, #17, and #22 are sensible post-release/post-MVP backlog items and do not block `v0.0.2-prealpha`.
