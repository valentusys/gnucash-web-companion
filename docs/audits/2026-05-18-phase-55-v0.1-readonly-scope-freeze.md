# Independent Audit — 2026-05-18 — Phase 55 v0.1 read-only scope freeze

## Executive summary

The project is ready to prepare a `v0.1.0-readonly` milestone plan, but it is not ready to publish v0.1 yet. The read-only/default-write safety boundary is intact, `v0.0.2-prealpha` is published, dogfood and troubleshooting documentation exist, and core backend/frontend checks are established. The main audit finding was documentation drift in `docs/ROADMAP.md`, which still described `v0.0.2-prealpha` as unpublished even though Phase 42 published it. That mismatch was accepted for engineer cleanup in Phase 55.

## Verdict

Ready to prepare v0.1 read-only.

This is not a v0.1 release approval. It means Phase 56 may prepare the `v0.1.0-readonly` plan/checklist. A v0.1 release should still require a dedicated release plan, fresh gate audit, green checks, and preferably clean local Docker smoke/dogfood evidence against disposable/copied data.

## Top blockers

None remain after the accepted documentation/status cleanup in this phase.

Resolved during Phase 55:

1. `docs/ROADMAP.md` release posture was stale: it said `v0.0.2-prealpha` was not published while README/PROJECT_STATUS/CHANGELOG and GitHub releases show it was published in Phase 42.

## Important non-blockers

1. GitHub issue #22 remains open for broader real-version GnuCash fixture coverage. Current generated fixture coverage is useful but not a broad desktop-version compatibility guarantee.
2. GitHub issues #11, #12, #13, and #17 remain open as future/backlog items; they do not block planning a read-only v0.1 milestone, but the v0.1 plan must decide explicitly what is in/out.
3. Live clean-machine Docker/runtime smoke was not executed in this audit because it needs an intentionally prepared local deployment and copied/disposable book. This should be a v0.1 release gate item, not silently treated as complete.
4. `SECURITY.md` is honest but still generic. A v0.1 plan should decide whether any additional deployment/security checklist is required before publication.

## Safety boundary

The read-only/default-write boundary remains intact:

- `apps/api/app/config.py` has `gnucash_writes_enabled: bool = False`.
- `docker-compose.yml` passes `GNUCASH_WRITES_ENABLED=${GNUCASH_WRITES_ENABLED:-false}`.
- `.env.example` sets `GNUCASH_WRITES_ENABLED=false`.
- Controlled-write validate/create/patch routes call `_ensure_writes_enabled(settings)` before book resolution, access checks, audit creation, or `_write_service_for()` construction.
- Disabled-write regression tests exist in `apps/api/tests/test_transaction_writes.py::TestWritesDisabledByDefault`.
- Money/filter code inspected in this pass uses `Decimal` for amount range filters; no new float-money path was identified.

No write-scope expansion was performed in Phase 55.
